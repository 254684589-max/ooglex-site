# 财务桑基

公开路径：`/apps/financial-sankey/`

中文页面。输入美股代码，画出最近一个报告期的三张桑基图：利润表、资产负债表、现金流量表。研究用，不是投资建议，也不是行情。

## 数据从哪来

只用美国证监会公开数据：

- 代码表：<https://www.sec.gov/files/company_tickers.json>
- 公司 XBRL：<https://data.sec.gov/api/xbrl/companyfacts/CIK##########.json>

没有 API key，也不抓 Sankify、FinGraphicx、Bloomberg 或其他付费站。

SEC 公平访问要求请求带能识别应用的 User-Agent。浏览器里的 `fetch` 不能改 User-Agent，而且 `data.sec.gov` 的响应没有 `Access-Control-Allow-Origin`。在 GitHub Pages 上直接读会失败。本页的做法：

1. 仍然先尝试直连 SEC。哪天接口允许跨域，同一套 JSON 就会直接出图。
2. 直连失败时，NVDA 和 MSFT 使用 `snapshots/` 里的摘录。摘录是 2026-10-21 从 companyfacts 裁下来的真实 us-gaap 科目，`demo` 为 `false`，不是模拟数。页面会写摘录时间。
3. 其他代码若已在代码表里，会显示公司名和 CIK，并给出 SEC 链接。把 companyfacts JSON 用「打开本地 JSON」选进来即可画图，文件只在浏览器里解析，不上传。

`tickers.json` 是 SEC 代码表的精简副本（代码、CIK、公司名）。`extract_snapshot.py` 用来重新裁摘录：它只请求上面两个公开地址。

## 图怎么读

条带宽度按美元。绿色是流入，红色是流出，蓝色是小计，金色是轧差。名称和金额同时写在表里，不靠颜色单独表达。

映射的是常见工商企业科目，例如营业收入、营业成本、研发费用、经营/投资/筹资现金。对不上的差额标成「轧差」或「未映射」，公式写在明细里。可能重叠的科目宁可不画，也不重复加总。

默认是最新年报（10-K，若只有 20-F 则用 20-F）。「最新季报」用最近一份 10-Q 里约一个季度的利润表和期末资产负债表。季报现金流量在 XBRL 里经常是年初至本季末，页面会单独写明，不能和单季利润表直接比较。

## 做不到的事

- 银行、保险，或没有营业收入科目的公司，可能只有说明、没有图。
- 净利润为负、所得税为收益时，利润表这一版不画，避免条带方向和金额相反。
- 资产负债表上的抵销项（综合亏损、库存股）从相邻条带里扣掉，原值留在表里。
- 没有把页面放进「最新消息」顶栏。那一排是五个新闻栏目，并且按手机宽度排过；这里是单独的研究页。
- 还没有同源代理。下一步如果要做，只转发 `data.sec.gov/api/xbrl/companyfacts/CIK##########.json`，在服务端加上 SEC 要求的 User-Agent，并限制频率。页面里的直连地址不用改。

数字对应的是申报文件里的 XBRL，可能和新闻稿里的四舍五入口径不同。
