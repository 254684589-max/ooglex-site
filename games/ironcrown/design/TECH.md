# 铁冠之争 THE IRON CROWN · 技术方案

> 路线图步骤 0.5 · 2026-09-27 · 状态：初稿，待所有者审阅
>

## 一、引擎与导出

| 项目 | 选择 | 依据 |
|---|---|---|
| 引擎 | **Godot 4.7.2**（与仓库其余三款 3D 游戏同版本） | 构建、测试、导出脚本现成 |
| 渲染器 | **GL Compatibility**（WebGL 2） | Godot 网页导出只支持这一种 |

## 三、Godot 工程结构

```
godot/
├── project.godot
├── core/        Events（信号总线）· GameState（旗标、声望、时间）· SaveGame · Settings · UiScale · InputSetup · Sfx
├── player/      FpController（CharacterBody3D + 相机：移动、视角、冲刺、蹲、跳、头部摆动）
│                Interactor（屏幕中心射线、交互提示）· Viewmodel（手中武器的显示与程序化挥动）
├── combat/      DamageCalc · MeleeAttack（挥砍瞬间的形状查询）· Stamina · HitFeedback（停顿、闪红、音效）
├── actors/      Npc（对话入口、作息点）· Enemy（状态机：巡逻 / 起疑 / 警觉 / 战斗 / 逃跑）· Perception（视野锥 + 听觉）
│                rig/（骨骼人形，参照 emberfall3d/godot/actors/rig/）
├── rpg/         Stats（属性、技能、专长）· Inventory · Equipment · Loot（搜刮）· Reputation
├── quest/       DialogueRunner（对话树解释器、条件与效果）· QuestLog · Flags
├── world/       Look（环境、雾、调色、画质档）· Lamp（街灯 / 窗光 / 火把）· Door · Container · 区域场景
├── ui/          Hud · DialoguePanel · InventoryPanel · QuestPanel · CharPanel · MapPanel · PauseMenu · TouchControls
├── data/        items.json · enemies.json · dialogue/<区域>.json · quests.json · flags.json · balance.json
├── scenes/      main.tscn · frostford.tscn（霜渡镇）· test_range.tscn（灰盒测试场）
```

分层沿用《打工》《余烬陷落》：**数据 → 规则（纯函数 / 管理器）→ 场景（表现）→ 界面**。规则层不持有场景节点，可以在无头模式下单元测试。

## 四、关键实现

### 4.1 第一人称控制器

- `CharacterBody3D`（胶囊高 1.8 米、半径 0.35 米）+ 头部节点 + `Camera3D`（视高 1.65 米）；水平转身、垂直俯仰（限制 ±85°）。
- 加速 / 减速平滑，贴墙滑动用 `move_and_slide()`。**台阶（1.2 已实现）**：Godot 4 的 `CharacterBody3D` 没有内置跨台阶，`FpController._try_step()` 用 `test_move()` 做「水平被挡 → 抬高 0.3 米不被挡 → 往前再往下探到平地 → 把身体抬上去」；落脚面太斜（超过 46°）不算台阶，所以陡坡上不去。`floor_snap_length` = 0.35 米，下台阶贴地不腾空。长楼梯仍建议碰撞做成斜坡，走起来更顺。
- **界面铺满画面的坑（1.2 发现）**：挂在 CanvasLayer 下的 Control 用 `set_anchors_preset(PRESET_FULL_RECT)` 只改锚点，尺寸仍是 0；要用 `set_anchors_and_offsets_preset()`。
- **无头测试的窗口只有 64×64**：测试开始时设 `get_tree().root.size = Vector2i(1280, 720)`。
- **网页指针锁定（实测）**：浏览器只允许在用户点击后锁定指针。点击画面时设置 `Input.mouse_mode = MOUSE_MODE_CAPTURED`；Esc 被浏览器用来释放锁定，游戏要监听释放并自动打开暂停菜单，而不是再抢回来。
- **手机**：左半屏虚拟摇杆移动、右半屏拖动转视角（按拖动像素 × 灵敏度，不是按屏幕比例），动作按钮在右下。触屏事件与模拟鼠标事件的区分沿用《余烬陷落》的经验（`TECH.md` 4.1：玩家控制只认真正的鼠标，触屏走 ScreenTouch / ScreenDrag）。
- 头部摆动、镜头震动受「减少动态效果」和设置开关控制。

### 4.2 交互

- 每个物理帧从相机中心发 2.5 米射线（**1.3 已实现**：`player/interactor.gd`），射线同时检测「世界」层（位值 1）与「可交互」层（位值 4），**第一个碰到的**是 `Interactable` 才算目标，所以隔着墙和东西不能交互；
  提示文字由目标提供（「交谈 · 玛蒂尔达」「打开 · 木门」「拾取 · 面包」）。`interact()` 返回结果字典（kind / toast / speech），由 main 显示，规则层不碰界面。
- 门（`world/door.gd`）：节点原点是门轴，门板沿本地 +X；打开时按玩家在门的哪一侧决定转 +90° 还是 -90°（总是转离玩家）。门是静态体，转动时不会推人，所以一定要转离玩家。
- 可拾取物只在「可交互」层，不挡路；碰撞体比外观大 0.1 米，好瞄。

### 4.3 近战

- 挥砍：在动画的「命中帧」做一次形状查询（相机前方 0.4–2.0 米的扇形盒），不用长期存在的 Area3D。
- 格挡 / 完美格挡：记录格挡按下的时刻，与敌人命中帧比较（`GDD.md` 第六节）。
- 命中停顿只冻结双方（局部），不改全局 `Engine.time_scale`（《余烬陷落》4.2 的做法）。
- 敌人攻击令牌：同时最多 2 个敌人持有「攻击令牌」，其余绕圈（`GDD.md` 6.2）。
- **2.4 已实现**：`combat/melee.gd`（状态：收剑 / 拔剑 / 持剑 / 蓄力 / 起手 / 挥砍 / 收招；输入只有 `press()` / `release()` / `toggle_draw()`，鼠标、F 键、触屏「攻」按钮和测试共用）；
  命中帧做一次 1.4 × 1.2 × 1.6 米的盒子查询（物理层 4「可受击」），取最近、且相机到目标的射线不被世界层挡住的一个；`combat/weapon_view.gd` 挂在相机下，姿势 = 位置 + 剑尖方向 + 剑面法线，插值出挥动。
  **坑**：剑身金属度高时在没有反射探针的场景里是黑的（改成 0.35）；竖屏时水平视野窄，姿势左右偏移按宽高比收拢；剑离相机近，贴墙时会插进墙里（以后用单独的渲染层或缩短剑程时再处理）；
  无头 Chromium 在指针锁定时每次按鼠标都补发 −640 像素的假位移（只影响自动化冒烟测试）；低帧率下拔剑途中的点击要排队，否则会丢。

### 4.4 敌人感知与寻路

- 视野锥（前方 110°、距离随光照变化：暗处 8 米、亮处 20 米）+ 视线射线 + 听觉（跑步、战斗的声音半径）。
- 寻路：手工区域在编辑器里预烘焙导航网格；导航参数对齐体素（《余烬陷落》4.1 的坑：半径是 `cell_size` 的整数倍）。
- **2.5 已实现**（`actors/enemy.gd`，数值在 `data/enemies.json`）：视野锥 + 射线，亮处看组 `light_source`（街灯、火把，元数据 `radius`）；听觉按玩家动静（跑 10 / 走 4 / 蹲 1.5 / 挥剑 8 米）；感知每 0.1 秒算一次；
  怀疑值 0..1（0.35 起疑、1 警觉，起疑后再看到涨三倍）；战斗中看不到 6 秒回到起疑。攻击令牌在 `combat/combat_director.gd`。随机数用「存档种子 + 敌人编号」做种子。
  **寻路还没上导航网格**：训练场是平地，直线走 + 碰撞滑动够用；敌人进街巷（阶段 3）时再烘焙导航网格。玩家的格挡、完美格挡、失衡与生命在 `combat/melee.gd`（`receive_hit()`）。

### 4.5 对话与任务

- 对话文件 `data/dialogue/<区域>.json`：节点表 + 选项（条件、效果）。**2.1 已实现节点与选项**（`quest/dialogue_runner.gd` 规则 + 校验、`ui/dialogue_panel.gd` 界面，打开时暂停、镜头转向说话人）；条件与效果在 2.2。**坑**：这个脚本用 `static var` 缓存时退出释放不掉（引擎报资源泄漏），改存 `Engine` 元数据；`run_tests.sh` 遇到退出泄漏判失败。条件与效果是一个小的白名单指令集（`flag`、`rep`、`skill_check`、`has_item`、`give_item`、`start_quest`、`advance_quest`、`start_combat`），**不执行任意表达式**。
- 对话检定的随机数：用「存档种子 + 检定编号」算出，读档不会改变结果（`GDD.md` 5.3）。**2.2 已实现**（`core/game_state.gd`）：哈希值只当随机数生成器的种子——直接取哈希低位时编号相近的检定分布不均（把握 70% 实测成功 85%）；掷过的检定结果记在 `checks` 里，2.8 一起存档。
- **任务（2.3 已实现）**：`data/quests.json` 定义任务（阶段、目标、`advance_when` 自动推进）与线索；状态在 `GameState`（`quests` / `clues` / `inventory`），`quest_event` 信号驱动屏幕提示；对话的条件与效果白名单扩展了任务、线索、物品几类，校验时检查编号都存在。
- **背包与搜刮（2.6 已实现）**：物品在 `data/items.json`；背包、装备、银币、搜刮记录在 `GameState`（`inventory` 是物品编号数组，同一物品可重复；`equipped` 部位 → 编号；`looted` 容器编号 → 剩下的东西），`inventory_changed` 信号驱动武器外观；
  面板外框共用 `ui/ui_kit.gd`。**坑**：自动换行的 Label 在第一次排版前按 0 宽度算最小高度，面板会被撑满整屏——先给宽度、排版一帧后再定滚动区高度。对话白名单加了 `silver`（条件）与 `pay`（效果）。
- 自动化测试遍历所有对话文件：每个节点可达、每个选项指向存在的节点、每个旗标都在 `flags.json` 里登记。

### 4.6 画面（参考图的雾夜）

| 手段 | 做法 | 状态 |
|---|---|---|
| 雾 | `Environment` 深度雾（蓝灰），加少量贴地的半透明雾面片随风缓慢移动 | 兼容渲染器没有体积雾，**实测**雾面片的排序与性能 |
| 窗光 | 窗户用自发光材质 + 窗外一张加法混合的光晕面片；不放真实光源 | —— |
| 街灯 / 火把 | 实时 `OmniLight3D`，按「视野内 ≤ 4 盏」布置，远处的灯只剩自发光 + 光晕 | 《余烬陷落》`world/torch.gd` 可参考 |
| 月光 | 一盏弱的冷色方向光，中档以上开阴影（近距离） | —— |
| 湿石板 | Poly Haven 石板贴图 + 调低粗糙度，让月光和灯光在路面上反光 | 兼容渲染器没有屏幕空间反射，靠高光和天空反射图 |
| 遮蔽 | 顶点色环境光遮蔽（墙脚、屋檐下） | 《余烬陷落》2.6 已验证 |
| 烘焙光照 | 本开发环境没有 Vulkan，**无法烘焙光照贴图**（《余烬陷落》2.3 实测）；默认不用 | 如需烘焙，要在有显卡的电脑上烘焙后提交 |
| 后期 | ACES 色调映射、轻微泛光、冷色调色、暗角 | —— |

- **遮挡剔除（1.4 已实测）**：网页导出模板在编译时去掉了遮挡剔除，场景里有 `OccluderInstance3D` 就会在浏览器控制台报 `Occlusion culling is disabled at build-time`。**网页版不用遮挡剔除**；靠按材质合并网格（每栋房子 ≤ 8 次绘制调用）和雾掩盖远景控制绘制量。
- **贴图映射（1.4 实测）**：三向投影（triplanar）每张贴图要采样三次，颜色 + 法线 + ARM 三张就是九次；本机软件渲染下帧率从 13.7（纯色）掉到 1–3。改为 `world/mesh_kit.gd` 生成网格时按每个面的平面方向算 UV（1 单位 = 1 米，材质 `uv1_scale` = 1 / 平铺米数）并生成切线，每张贴图只采样一次。用 `QuadMesh` / `BoxMesh` 的东西（门）也改用 MeshKit，比例才一致。
- **阴影（1.4 实测）**：方向光默认 4 段级联阴影会把场景重画 4 遍（绘制调用 154 → 393）；中档改为 1 段（`SHADOW_ORTHOGONAL`，25 米），高档 2 段。
- **光晕**：加法混合的光晕面片要关雾（否则雾色被叠亮），关雾后必须自己随距离淡出（`distance_fade` 反向：12 米内完整、30 米外消失），否则远处浓雾里剩一片亮点阵。
- **雾**：霜渡镇用深度雾（3 米开始、36 米吞没，曲线 0.85）+ 贴地高度雾 + 17 片噪声雾带；雾带开销在兼容渲染器下不明显。
- 工具：`tools/shots_web.js`（3 个固定机位截图 + `IC_PERF`）、`tests/perf_stats.tscn`（本机逐项关掉做开销对照）。

### 4.7 存档

- 网页上写入浏览器 `localStorage`（键名 `ooglex.ironcrown.v1`，《余烬陷落》用的方式），其他平台写 `user://`。
- JSON，带 `version`；每个栏位保留「当前 + 上一份」，读档失败回退上一份，**不用空数据覆盖有效存档**。
- 存档只记录「与初始状态的差异」（已拾取、已死亡、已打开的对象用唯一 ID 记录），场景本身每次重新加载。

### 4.8 音频

- 三条总线：音乐、音效、环境声。首发音效用代码合成（参照《余烬陷落》`core/sfx.gd`），环境声（风、河水、远处狗叫）优先找 CC0 录音，记入 `SOURCES.md`。
- 浏览器要求用户交互后才能出声：第一次点击「开始」时启动音频。

## 五、画质分档

| 档位 | 3D 分辨率 | 月光阴影 | 实时点光源 | 泛光 | 雾面片 |
|---|---|---|---|---|---|
| 低（触屏默认） | 0.75× | 无 | 2 | 无 | 少 |
| 中（默认） | 1.0× | 近距离 | 4 | 有 | 正常 |
| 高 | 1.0× + 抗锯齿 | 近距离 + 灯光阴影 1 盏 | 6 | 有 | 正常 |

网页 `?q=low|medium|high` 可强制档位（沿用《余烬陷落》）；暂停菜单也能切换。性能浮层：F3 / 暂停菜单 / `?perf=1`（1.5）；`?perf=1` 自动在 3 个机位各测 3 秒并把结果表显示在画面上（真机反馈用），`?perf=1&view=N` 只测一次不显示浮层（截图工具用）。

## 六、包体与加载

- 加载画面显示真实进度与失败重试（沿用 `web/shell.html`）。

## 八、安全与隐私

纯单机，不收集个人数据，不发外部网络请求（章节包只访问同源静态文件）；代码与存档里不放任何密钥。

## 九、主要技术风险

| 风险 | 影响 | 应对 | 何时验证 |
