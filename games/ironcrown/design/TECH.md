## 四、关键实现

### 4.1 第一人称控制器

- `CharacterBody3D`（胶囊高 1.8 米、半径 0.35 米）+ 头部节点 + `Camera3D`（视高 1.65 米）；水平转身、垂直俯仰（限制 ±85°）。
- 加速 / 减速平滑，贴墙滑动用 `move_and_slide()`。**台阶（1.2 已实现）**：Godot 4 的 `CharacterBody3D` 没有内置跨台阶，`FpController._try_step()` 用 `test_move()` 做「水平被挡 → 抬高 0.3 米不被挡 → 往前再往下探到平地 → 把身体抬上去」；落脚面太斜（超过 46°）不算台阶，所以陡坡上不去。`floor_snap_length` = 0.35 米，下台阶贴地不腾空。长楼梯仍建议碰撞做成斜坡，走起来更顺。
- **界面铺满画面的坑（1.2 发现）**：挂在 CanvasLayer 下的 Control 用 `set_anchors_preset(PRESET_FULL_RECT)` 只改锚点，尺寸仍是 0；要用 `set_anchors_and_offsets_preset()`。
- **无头测试的窗口只有 64×64**：测试开始时设 `get_tree().root.size = Vector2i(1280, 720)`。
- **网页指针锁定（实测）**：浏览器只允许在用户点击后锁定指针。点击画面时设置 `Input.mouse_mode = MOUSE_MODE_CAPTURED`；Esc 被浏览器用来释放锁定，游戏要监听释放并自动打开暂停菜单，而不是再抢回来。
- **手机**：左半屏虚拟摇杆移动、右半屏拖动转视角（按拖动像素 × 灵敏度，不是按屏幕比例），动作按钮在右下。触屏事件与模拟鼠标事件的区分沿用《余烬陷落》的经验（`TECH.md` 4.1：玩家控制只认真正的鼠标，触屏走 ScreenTouch / ScreenDrag）。
- 头部摆动、镜头震动受「减少动态效果」和设置开关控制。

- **第三人称越肩（2.9，D6）**：相机仍挂在头部节点下，第三人称时本地偏移 (0.55, 0.25, 2.6)，每帧从眼睛向偏移点打世界层射线，撞墙就收到墙前 0.25 米（往前收快、往后退慢）。
  瞄准相关的代码一律用 `FpController.aim_origin()`（眼睛）而不是相机位置：交互射线从相机穿过屏幕中心、只认离眼睛 2.5 米内的东西；命中盒子、敌人视线都从眼睛算。人物在 `player/avatar.gd`（2.9 是占位人形，A.1 换成人物模型，见 4.4b）。

### 4.2 交互

- 每个物理帧从相机中心发 2.5 米射线（**1.3 已实现**：`player/interactor.gd`），射线同时检测「世界」层（位值 1）与「可交互」层（位值 4），**第一个碰到的**是 `Interactable` 才算目标，所以隔着墙和东西不能交互；
  提示文字由目标提供（「交谈 · 玛蒂尔达」「打开 · 木门」「拾取 · 面包」）。`interact()` 返回结果字典（kind / toast / speech），由 main 显示，规则层不碰界面。
- 门（`world/door.gd`）：节点原点是门轴，门板沿本地 +X；打开时按玩家在门的哪一侧决定转 +90° 还是 -90°（总是转离玩家）。门是静态体，转动时不会推人，所以一定要转离玩家。
- 可拾取物只在「可交互」层，不挡路；碰撞体比外观大 0.1 米，好瞄。

### 4.3 近战

- 挥砍：在动画的「命中帧」做一次形状查询（相机前方 0.4–2.0 米的扇形盒），不用长期存在的 Area3D。
- 格挡 / 完美格挡：记录格挡按下的时刻，与敌人命中帧比较（`GDD.md` 第六节）。
- 命中停顿只冻结双方（局部），不改全局 `Engine.time_scale`（《余烬陷落》4.2 的做法）。
- 敌人攻击令牌：同时最多 2 个敌人持有「攻击令牌」，其余绕圈（`GDD.md` 6.2）。
- **2.4 已实现**：`combat/melee.gd`（状态：收剑 / 拔剑 / 持剑 / 蓄力 / 起手 / 挥砍 / 收招；输入只有 `press()` / `release()` / `toggle_draw()`，鼠标、F 键、触屏「攻」按钮和测试共用）；
  命中帧做一次 1.4 × 1.2 × 1.6 米的盒子查询（物理层 4「可受击」），取最近、且相机到目标的射线不被世界层挡住的一个；`combat/weapon_view.gd` 挂在相机下，姿势 = 位置 + 剑尖方向 + 剑面法线，插值出挥动。
  **坑**：剑身金属度高时在没有反射探针的场景里是黑的（改成 0.35）；竖屏时水平视野窄，姿势左右偏移按宽高比收拢；剑离相机近，贴墙时会插进墙里（以后用单独的渲染层或缩短剑程时再处理）；
  无头 Chromium 在指针锁定时每次按鼠标都补发 −640 像素的假位移（只影响自动化冒烟测试）；低帧率下拔剑途中的点击要排队，否则会丢。
- **3.3 徒手**：`Melee.arms()` = 装备的武器，没装备武器或打架不许动刀（`fists_only`）时是 `Melee.FISTS`（基础伤害 5，用格斗技能）。出招时机和剑共用 `TIMING`（第三人称动作对齐不用另算），
  够得着 1.5 米（盒子深度按 `reach_far()` 缩短）、体力 ×0.7。`WeaponView` 的 fists 外观是两只占位拳头：右拳按 `FIST_POSES` 出拳，左拳平时护在胸前、格挡时跟着举起（`off_raise`）；拳头时 `WeaponView` 本身不动，两只拳头各摆各的（左拳镜像）。
  武器和拳头之间换时，正拿着就先收起来；武器换武器仍然直接换到手里。格斗专长：连拳（`combo3`，和剑术「连环」同一个效果名，按当前武器的技能查）、重拳（`fist_stagger`）、硬骨头（`guard_cheap`）。
- **不致命的打斗**（3.3）：敌人数据 `nonlethal: true`（`drunk`）时它的生命最少留 1、到 `flee_below` 一定认输；它打玩家的攻击带 `nonlethal`，玩家生命打到 `Melee.KO_FLOOR`（25）就算被打倒（`knocked_out`，不出倒下界面）。
  对话效果 `{"brawl": 种类, "win": 旗标, "lose": 旗标}` 只能放在结束对话的选项上；对话关上后 `main.start_brawl()` 用 `combat/brawl.gd`：说话的 NPC 藏起来、原地生成同名敌人（`Enemy.display_override`）直接进入战斗（`engage()`），
  场景里没有 `CombatDirector` 就补一个；打赢（对方认输）跪 1.2 秒后变回 NPC，输了 NPC 回原处；结束时设旗标、自动存档。打的时候 `main.in_combat()` 为真（不能存档、出门、和别人搭话）。
  **坑**：`process_mode = DISABLED` 的物理体会被移出物理世界，打不到（测试里想让敌人不还手，改成让它跪下认输或用命中停顿冻住）；敌人看不见你会回去巡逻，打架的敌人每帧都被拉回战斗。网页 `?area=tavern&brawl=1` 一进门就开打（截图与冒烟测试用，不设旗标）。

### 4.4 敌人感知与寻路

- 视野锥（前方 110°、距离随光照变化：暗处 8 米、亮处 20 米）+ 视线射线 + 听觉（跑步、战斗的声音半径）。
- 寻路：原计划手工区域在编辑器里预烘焙；3.4 实测运行时烘焙只要几毫秒到十几毫秒，改为载入区域时烘焙（区域全是代码搭的，不用另外维护一份烘焙结果）；导航参数对齐体素（《余烬陷落》4.1 的坑：半径是 `cell_size` 的整数倍）。
- **2.5 已实现**（`actors/enemy.gd`，数值在 `data/enemies.json`）：视野锥 + 射线，亮处看组 `light_source`（街灯、火把，元数据 `radius`）；听觉按玩家动静（跑 10 / 走 4 / 蹲 1.5 / 挥剑 8 米）；感知每 0.1 秒算一次；
  怀疑值 0..1（0.35 起疑、1 警觉，起疑后再看到涨三倍）；战斗中看不到 6 秒回到起疑。攻击令牌在 `combat/combat_director.gd`。随机数用「存档种子 + 敌人编号」做种子。
  玩家的格挡、完美格挡、失衡与生命在 `combat/melee.gd`（`receive_hit()`）。
- **3.4 导航网格**：`world/nav_builder.gd`（思路复制自《余烬陷落》的 `nav_builder.gd`）在区域搭好后**运行时同步烘焙**：源几何是区域里物理层 1 的静态碰撞体（房子、墙、桌子、井、站着的 NPC、关着的门），
  范围按 `Areas.NAV_BOUNDS`（主街、酒馆、训练场；墓园、小教堂、测试场没有敌人，不烘焙）。参数：格子 0.25 米、高度格 0.05 米、半径 0.5 米、高 1.75 米、攀爬 0.25 米；导航地图的格子大小跟着改成一样。
  实测（无头、本机）：主街 149 个多边形约 10 毫秒，酒馆约 2 毫秒，训练场约 4 毫秒；网页实测见 `TEST_REPORT.md`。房子之间 1.3 米的窄缝按半径收缩后走不过去，房子背后的人要从一排房子的尽头绕到街上。
  敌人（`actors/enemy.gd`）挂一个 `NavigationAgent3D`，`_steer()`：有网格就沿路径走（目标挪动 0.5 米或路径用了 0.5 秒才重新寻路），没有网格（或刚载入还没同步）就直线走。
  用在：战斗中隔着房子看不见你时绕过来（脸朝走的方向）、起疑时去你最后出现的地方、巡逻点之间、逃跑时往远处能走到的地方；看得见你且 2.5 米以内时直接冲。巡逻点贴着墙够不到时，走到路径终点也算到了。
  **坑**：高度格 0.25 米时网格面比地面高 0.5 米（导航代理按三维距离判断到没到路径点），改成 0.05 米后贴着地面（0.1 米）；`-s` 调试脚本里用不了 `Enemy.make()` 这类静态方法（全局类没加载全），改用 `load(...).new()`。

### 4.4b 人物模型与动作（A.1，D4 = B）

- **素材**：Quaternius 的 Universal Base Characters（男性底模）+ Universal Animation Library 1 / 2，全部 CC0，同一套 65 根骨头的骨架，动作不用重定向。来源与处理见 `assets/SOURCES.md`。
- **代码**：`actors/character_model.gd`（`CharacterModel`：加载底模 + 动画库、`play_loop` / `play_once` / `hold`、纯函数 `pick_locomotion` / `light_attack`；玩家、NPC、敌人以后共用）；
  `player/avatar.gd`（`PlayerAvatar`：按 `Melee.state` 与移动速度选动作，第一次显示第三人称时才加载模型）。**动作与「角色」的对应、播放速度参考值、命中时刻都在 `data/character_anims.json`**，改了之后重新运行
  `godot --headless --path games/ironcrown/godot -s ../tools/build_character_anims.gd` 重新打包动画库（只带用到的动作，原包的 glb 每个 7.6 MB）。
- **与近战对齐**：动作播放速度 = 动作里的命中时刻（`impact`，从每帧右手位置的速度峰值量出）÷ 近战从起点到命中帧的时间（`Melee.TIMING`）。重击蓄力时把动作从 0 推到 `wind_peak`（抬到最高）停住，松手后从那里劈下。
  改了 `Melee.TIMING` 或换了动作，测试里「动作播放速度在合理范围」和「命中帧动作在最前」两组检查会报出来。
- **坑**：
  - glTF 人物面朝 **+Z**，游戏里向前是 -Z：`CharacterModel` 外面转 180°。
  - 动作库只有朝前走 / 跑 / 蹲走，没有侧走、倒走：`PlayerAvatar` 把身体转向移动方向，超过 100° 就倒放前进动作。
  - 步行速度 3 米 / 秒对走路动作（约 1 米 / 秒）太快，改用放慢到 ×0.56 的慢跑动作；速度参考值从 `UAL1_Standard_RM` 的根骨骼位移量出。
  - **倒下时游戏树会暂停**（`main._on_defeated`），动画也会停在挨打的一帧：`PlayerAvatar` 在 `defeated` 时把自己的 `process_mode` 改成 ALWAYS，倒地动作才播得出来（测试抓到的）。
  - 无头模式下 `Skeleton3D.get_bone_global_pose()` 读到的是缓存的旧值；测试用 `get_bone_pose_rotation()`（动画写进去的局部姿势）判断动作有没有驱动骨架。
  - 贴图：2048² 的 PNG 导入时缩到 1024、Basis 压缩、生成 mipmap（和 Poly Haven 贴图同一套设置），整套人物网页包里约 4 MB；glTF 材质默认双面，导入后改成背面剔除，并加一点点自发光，背光时不会变成黑影。
  - **徒手动作**（3.3）：举拳待机停在 `Punch_Jab` 第 0 帧（护脸架势），轻拳 `Punch_Jab`（左手刺拳）/ `Punch_Cross`（右手直拳），重拳借 `OverhandThrow`（抡到身后 0.25 秒、砸下 0.36 秒；手是张开的，占位），
    空手格挡停在 `Idle_Shield_Loop` 第 0 帧（小臂横在胸前）。`Melee_Hook` 看名字像勾拳，其实是带兵器的跳劈，没用。命中时刻用脚本逐帧量手骨位置得出（出拳那只手最靠前的时刻）。
  - 本环境可以用 `xvfb-run` + Mesa 软件渲染做离屏截图：`tools/character_sheet.gd` 把人物摆在几个动作的某一刻渲成拼图，校准拿剑位置用的（剑身沿手骨 +Z 再向 +Y 偏 45°，剑面法线朝手心；免费动作库没有带剑的标准握法，朝向是按手骨轴向估的，待机时剑偏向右侧垂下，之后可手调或换带剑的动作）。

### 4.5 对话与任务

- 对话文件 `data/dialogue/<区域>.json`：节点表 + 选项（条件、效果）。**2.1 已实现节点与选项**（`quest/dialogue_runner.gd` 规则 + 校验、`ui/dialogue_panel.gd` 界面，打开时暂停、镜头转向说话人）；条件与效果在 2.2。**坑**：这个脚本用 `static var` 缓存时退出释放不掉（引擎报资源泄漏），改存 `Engine` 元数据；`run_tests.sh` 遇到退出泄漏判失败。条件与效果是一个小的白名单指令集（`flag`、`rep`、`skill_check`、`has_item`、`give_item`、`start_quest`、`advance_quest`、`start_combat`），**不执行任意表达式**。
- **3.9 灰色选项**：`DialogueRunner.option_state()` 把条件分成「差东西」（`silver`、`has_item`，`RESOURCE_KEYS`）和剧情条件；剧情条件不满足 → 隐藏，只差东西 → `locked`，`option_needs()` 拼出「需要……」；选项写 `"locked": "hide"` 时照旧隐藏（校验：只能写 `hide`，而且要有银币或物品条件）。
  `options()` 仍只返回能选的（`choose(i)` 的下标、数字键、老测试都不变），界面用 `entries()` 按原顺序画，灰色按钮 `disabled`、`focus_mode = NONE`（方向键跳过）、不编号。
- 对话检定的随机数：用「存档种子 + 检定编号」算出，读档不会改变结果（`GDD.md` 5.3）。**2.2 已实现**（`core/game_state.gd`）：哈希值只当随机数生成器的种子——直接取哈希低位时编号相近的检定分布不均（把握 70% 实测成功 85%）；掷过的检定结果记在 `checks` 里，2.8 一起存档。
- **任务（2.3 已实现）**：`data/quests.json` 定义任务（阶段、目标、`advance_when` 自动推进）与线索；状态在 `GameState`（`quests` / `clues` / `inventory`），`quest_event` 信号驱动屏幕提示；对话的条件与效果白名单扩展了任务、线索、物品几类，校验时检查编号都存在。
- **背包与搜刮（2.6 已实现）**：物品在 `data/items.json`；背包、装备、银币、搜刮记录在 `GameState`（`inventory` 是物品编号数组，同一物品可重复；`equipped` 部位 → 编号；`looted` 容器编号 → 剩下的东西），`inventory_changed` 信号驱动武器外观；
  面板外框共用 `ui/ui_kit.gd`。**坑**：自动换行的 Label 在第一次排版前按 0 宽度算最小高度，面板会被撑满整屏——先给宽度、排版一帧后再定滚动区高度。对话白名单加了 `silver`（条件）与 `pay`（效果）。
- **成长与声望（2.7 已实现）**：`data/progression.json`；`GameState.train(技能, 进度)` 是唯一的涨技能入口（命中、格挡、检定、搜刮、潜行都调它），专长效果只认 `PERK_EFFECTS` 白名单，各系统用 `has_perk()` 查；声望 `change_rep()` 发 `rep_changed` 信号。
  **坑**：停掉处理（`PROCESS_MODE_DISABLED`）的物理体默认会被移出物理世界（`disable_mode = REMOVE`），测试里冻住的敌人砍不到，要改成 `DISABLE_MODE_KEEP_ACTIVE`；字体子集只有 GB2312 的几何符号（■□▲◆◇↑↓），没有 ▰▱▼。
- **抉择与尾声（3.7 已实现）**：抉择记在**字符串旗标** `prologue_edric`（`deliver` / `release` / `extort`），对话条件用 `{"flag": 名, "eq": 值}` 分支；`GameState.has_flag()` 按类型判断真假（布尔 / 数字照旧，字符串非空即真）。
  **坑**：原来写成 `bool(flags[名])`，字符串值会报「Nonexistent 'bool' constructor」，渡口和小教堂判断「做没做抉择」全错。
  对话白名单加了 `earn`（收银币，大于 0）和 `ending`（结束画面编号，只认 `EndingPanel.ENDINGS`）：`ending` 只记在 `GameState.pending_ending`，对话关上后 `main.show_ending()` 打开 `ui/ending_panel.gd`（暂停、显示鼠标、按抉择写回顾，宽度跟窗口收；HUD 和触屏按钮先藏起来，否则提示和「挡」「攻」会叠在回顾文字上，关掉画面再还原）。
  「在雾里再走走」关掉画面接着玩，「从头再来」= `GameState.new_game()` + 重新载入（存档不动）。渡口的对话关上时 `Ferry.refresh()` 按旗标撤掉埃德里克和塞拉斯、放奥尔本修士；修士在渡口时小教堂里没有他，交完书回小教堂（`after_book`）。
  网页 `?ending=deliver|release|extort` 直接打开结束画面（截图与冒烟测试用，不改旗标）。
- 自动化测试遍历所有对话文件：每个节点可达、每个选项指向存在的节点、每个旗标都在 `flags.json` 里登记。

- **遮挡剔除（1.4 已实测）**：网页导出模板在编译时去掉了遮挡剔除，场景里有 `OccluderInstance3D` 就会在浏览器控制台报 `Occlusion culling is disabled at build-time`。**网页版不用遮挡剔除**；靠按材质合并网格（每栋房子 ≤ 8 次绘制调用）和雾掩盖远景控制绘制量。
- **贴图映射（1.4 实测）**：三向投影（triplanar）每张贴图要采样三次，颜色 + 法线 + ARM 三张就是九次；本机软件渲染下帧率从 13.7（纯色）掉到 1–3。改为 `world/mesh_kit.gd` 生成网格时按每个面的平面方向算 UV（1 单位 = 1 米，材质 `uv1_scale` = 1 / 平铺米数）并生成切线，每张贴图只采样一次。用 `QuadMesh` / `BoxMesh` 的东西（门）也改用 MeshKit，比例才一致。
- **阴影（1.4 实测）**：方向光默认 4 段级联阴影会把场景重画 4 遍（绘制调用 154 → 393）；中档改为 1 段（`SHADOW_ORTHOGONAL`，25 米），高档 2 段。
- **光晕**：加法混合的光晕面片要关雾（否则雾色被叠亮），关雾后必须自己随距离淡出（`distance_fade` 反向：12 米内完整、30 米外消失），否则远处浓雾里剩一片亮点阵。
- **雾**：霜渡镇用深度雾（3 米开始、36 米吞没，曲线 0.85）+ 贴地高度雾 + 17 片噪声雾带；雾带开销在兼容渲染器下不明显。
- 工具：`tools/shots_web.js`（3 个固定机位截图 + `IC_PERF`）、`tests/perf_stats.tscn`（本机逐项关掉做开销对照）。

### 4.7 存档

- 网页上写入浏览器 `localStorage`（键名 `ooglex.ironcrown.v1`，《余烬陷落》用的方式），其他平台写 `user://`。
- JSON，带 `version`；每个栏位保留「当前 + 上一份」，读档失败回退上一份，**不用空数据覆盖有效存档**。
- 存档只记录「与初始状态的差异」（已拾取、已死亡、已打开的对象用唯一 ID 记录），场景本身每次重新加载。
- **2.8 已实现**：`core/saves.gd`（自动加载 `Saves`）。栏位 slot1–3 / auto / quick；读档 = `GameState.from_dict()` + `GameState.pending_load`（场景、玩家）+ 重新载入场景，`main` 启动时取走。
  捡走的地上物品用 `Pickup.pickup_id` 记进 `GameState.picked`；倒下的敌人记进 `GameState.dead`（编号 → 位置），`Enemy._ready` 里直接摆成倒下的样子、不再扣声望。
  **坑**：`JSON.parse_string` 解析失败会打引擎报错，坏档要用 `JSON.new().parse()`；浏览器里 F5 是刷新页面，快速存档用 F8；自动化测试检测到命令行里的 `res://tests/` 时改用 `user://test_saves/`，不碰真存档。
  不存：门的开关、进行到一半的对话。**3.5 起**求饶（或逃跑后认输）的敌人记进 `GameState.yielded`（编号 → 跪下的位置），读档后还跪着；求饶的人和倒下的人一样留一个搜刮点（同一个 `loot:编号`，只留一个），求饶以后又被杀就改记进 `dead`。
  旧存档没有 `yielded` 字段，按空的读。

### 4.7b 区域与切换（3.1）

- **区域 = 一个名字**（`world/areas.gd` 的 `Areas.NAMES`：`frostford`、`tavern`、`test_range`、`arena`）。`main.area` 决定搭哪个场景、用室内还是室外的光；存档里的 `scene` 字段就是区域名（`Saves.SCENE_NAMES = Areas.NAMES`）。
- **门通往别处**：`Door.to_area` / `to_spawn`（房子的门规格里写 `{"to_area": "tavern", "to_spawn": "front", "verb": "进入"}`）。交互结果 `kind = "travel"` → `main.travel()`：战斗中或倒下了走不开；先淡出（0.25 秒，减少动态效果时直接切），
  把「去哪个区域、站哪个出生点、生命 / 体力 / 蹲着」放进 `GameState.pending_load`，**重新载入主场景**（和读档同一条路；`GameState` 是自动加载的，任务、背包、已拾取都不受影响）。
  `main._ready` 看到 `pending_load.spawn` 就把玩家放到 `Areas.spawn(区域, 名字)`，淡入、提示区域名、关掉开场操作提示，**自动存档到「自动存档」栏位**（GDD 第十节「进入新区域时」）。
- **命名出生点**：各区域脚本的 `SPAWNS`（名字 → [位置, 水平朝向（度，0 = 面朝 -Z，正 = 向左转）]）。固定机位 `VIEWS` 也按区域取（网页 `?area=tavern&view=N`）。
- **3.6**：桦林南头 → `ferry`（渡口，室外，`world/ferry.gd`，出生点 `north`；桦林多了出生点 `south`）。岸上雪地有厚度、河面是低一截的深色平面，岸边和码头两侧是看不见的栏杆；码头面高 0.25 米（攀爬 0.3 米以内，走得上去，导航网格也铺上去）。
  **对峙转战斗**（`combat/encounter.gd`）：区域里一组 NPC 进组 `encounter:<编号>`、带元数据 `enemy_kind` / `enemy_id`；对话效果 `{"fight": 编号, "win": 旗标}` 让它们原地换成同名敌人开打（真打：会死人、声望照常变），全部倒下 / 认输 / 逃跑算打赢；`{"leave": 编号}` 让它们走掉。
  区域搭场景时按存档还原：编号在 `GameState.dead` / `yielded` 里的直接放敌人（倒着 / 跪着、能搜身），说服走了（旗标）的不放，其余放 NPC。打的时候 `main.in_combat()` 为真。
  头目 `outlaw_boss`（「灰手」奥弗）：`kick_chance` 出踢（起手冒「踢！」，`Melee.receive_hit` 里 kind = kick 举着格挡也破防）；`flank_call` 第一次掉到半血喊「包抄他！」，附近的同伙立刻冲上来、一左一右往两侧绕。逃跑一开始也记进 `yielded`（读档后按认输算）。
  `Birch.add_tree()` 抽成公用的，渡口岸上也种一片白桦。
- **3.5**：主街南门（`Frostford.SOUTH_GATE_Z`，出生点 `south_gate`）→ `birch`（镇外桦林，室外，`world/birch.gd`，出生点 `north`）；桦林南头「去渡口的路」先锁着（渡口在 3.6）。
  白桦是代码搭的（细长树干 + 树梢几根枝条，96 棵合成一个网格，每棵一个圆柱碰撞体）；没有现成的白桦贴图，`Look.birch()` 在主线程用固定种子画一张 64 × 128 的树皮（灰白底、横向皮孔、几块深斑），不新增外部素材。
  哨卡的三个无旗者是 `Enemy`（`clubber` × 2 + `outlaw_leader`），营火在组 `light_source`（半径 7 米）；进桦林时底部提示换成拿武器战斗的教学（STORY 第三节）。任务阶段的 `advance_when` 多了 `{"clue": 线索, "to": 阶段}`。
- **3.2 起的区域**：`frostford`（主街）→ 酒馆门 → `tavern`；主街右手边窄巷口的木门 → `churchyard`（墓园，室外）→ 小教堂门 → `chapel`（室内）。
- **钥匙门**（3.2）：`Door.key_item`。锁着的门身上有那把钥匙就打开（提示「用墓园钥匙打开了……」），没有就提示 `locked_text`。门开着的状态不存档，读档后要再开一次（钥匙还在身上，按一下就开）。
- **带线索的物品**（3.2）：`data/items.json` 里写了 `"clue"` 的物品，`GameState.add_item()` 时自动记下那条线索（墓室里那封没写完的信）；信的全文写在物品说明里，背包里选中就能读。
- **室内**（`Areas.INDOOR`）：没有月光与夜雾，暖色的暗环境光（0.5）+ 薄烟似的指数雾；亮度来自炉火（`Tavern.FireLight`，减少动态效果时不闪）、油灯、蜡烛，室内一共 3 盏点光源。
- **坑**：
  - 用 `godot -s 脚本` 跑的工具脚本里，**不能直接写依赖自动加载（Settings、GameState）的类名**（比如 `Areas` → `Frostford` → … → `Settings`）：脚本在自动加载注册之前编译，会报「Identifier not found: Settings」，后面的脚本全部编译失败、场景跑一半卡住。截图工具只能在运行时 `load()` 场景，不引用这些类。
  - 新对话很容易用到字体子集里没有的字（这次是「樵」「瞟」「醺」「噜」）：自动化测试会报出来，换常用字，或者重新跑 `tools/build_font.py`。
  - 换区域靠重新载入整个场景，门开着、敌人半血之类的状态不保留（和读档一样，见 4.7）；以后室外区域连成片时再考虑不重载的流式加载。

### 4.8 音频

- 三条总线：音乐、音效、环境声。首发音效用代码合成（参照《余烬陷落》`core/sfx.gd`），环境声（风、河水、远处狗叫）优先找 CC0 录音，记入 `SOURCES.md`。
- 浏览器要求用户交互后才能出声：第一次点击「开始」时启动音频。
- **3.8 已实现的第一个声音：开场钟声**（`core/bell.gd`）。不用外部素材：按教堂大钟的泛音（嗡音、基音、小三度、五度、八度和几条高泛音，各自指数衰减，嗡音和基音各有一条差一点的产生「颤」）在代码里合成 4.5 秒、22050 Hz、16 位单声道的 `AudioStreamWAV`，开头 25 毫秒敲击噪声，最后一道 2.4 kHz 低通（隔着雾的远处）。
  正弦用旋转递推（不逐采样调 `sin`），本机合成约 50 毫秒；在开场标题卡显示的第 3 帧合成，不在玩家点下去的那一刻卡一下。`AudioStreamPlayer` 的 `max_polyphony = 3`，三下钟声的余音叠在一起。暂停菜单「声音」关掉时不合成、不播放（字幕照样有）。总线、脚步与刀剑声仍在 A.3。

### 4.9 开场与教学提示（3.8）

- **开场**（`scenes/opening.gd`、`ui/title_card.gd`）：`Opening.wanted()` 判断——不是读档 / 换区域进来的、在主街、网址没带 `view` / `area` / `test` / `ending` / `brawl` / `perf`、旗标 `opening_done` 没设——才播。玩家站到 `Frostford.SPAWNS.manor`（宅邸门口、背对大门，管家在身后 2.3 米，转身就够得着说话）。
  标题卡「序章 / 霜渡镇之夜 / 灰鲸河畔 · 入夜」不挡点击；第一下点击 / 按键 / 触摸开始（网页要有一次用户操作才能出声）。**坑**：触屏按钮在 `_input` 里把触摸标成已处理，主场景收不到；开场节点是主场景最后加进去的，最先收到输入，所以「第一下」的判断放在开场节点自己的 `_input`，而且不吞掉这次输入（点击照样锁定鼠标、摇杆照样按下）。
  钟敲三下（间隔 2.4 秒），6.6 秒后管家喊「誓剑大人！请留步——」，设 `opening_done`（代码里设置的旗标在 `flags.json` 的 `set_in` 写 `.gd`，旗标登记检查不去对话里找它）。从头再来（新游戏）会再播一次。
  自动化测试里默认跳过（`test_runner` 设 `Engine` 元数据 `ic_skip_opening`），`opening` 组单独测；无头模式帧很快，测试里直接把开场的时钟拨过喊人的时刻。
- **教学提示**（`data/tips.json`，`main.show_tip()`）：每条只显示一次，看过的记在 `GameState.tips_seen`（进存档）；暂停菜单「教学提示」可以关。底部提示被占着（上一条没消失）或游戏暂停（面板开着）时排队，换区域时没轮到的带过去（`GameState.pending_tips`）。
  触发点：开场开始（走动）、管家喊人（转身说话，`now = true` 立刻换掉上一条）、接任务、拿线索、声望变化、背包变化、对准可搜刮的东西、第一次走进别处（自动存档）；检定的提示显示在对话面板里（游戏暂停时底部提示看不到）。酒馆打架、桦林的操作说明每次进去都显示，不在这里。
- 暂停菜单多了「声音」「教学提示」两个开关；操作说明只写这台设备的（手机竖屏上放不下两段）。
- **触屏排版**：底部提示（0.62 屏高）和 NPC 字幕（0.72）原来会被右下角的按钮列压住（`TouchControls.buttons_rect()`）。触屏按钮显示时：横屏（摇杆和按钮列之间还剩 300 像素以上）提示和字幕收窄到中间、字幕贴底；竖屏挪到上半屏（字幕 0.28 屏高，提示接在字幕下面）。矮屏幕上提示总放在字幕上面，不叠在一起。
- 管家在序章结束后有自己的台词（交出：少爷回来了；放走 / 勒索：问有没有消息），不再把主线重新派一遍（全流程测试抓到的）。

### 4.10 军阵战斗（D8「中型战斗」，阶段 B；B.1 已实现，B.2 起按下面的思路做）

**实测依据**（`tests/army_bench.tscn`，网页版用 `tools/army_bench_web.sh`；数字详见 `TEST_REPORT.md` 2026-10-04「军队规模评估」）：
在训练场里放 N 个现有的 `Enemy`（完整 AI）全部冲向玩家（所有人挤成一团，是最坏情况），网页（WASM，云端测试机 CPU、无头 Chromium）每帧逻辑耗时：

| 同屏士兵 | 占位胶囊 | 人物模型 + 骨骼动作 |
|---|---|---|
| 50 | 6.1 毫秒 | 6.7–7.8 毫秒 |
| 60 | —— | 9.2 毫秒 |
| 100 | 10.2 毫秒 | 15.2 毫秒 |
| 200 | 19.2 毫秒 | 27.4 毫秒 |

- 每个兵约 0.12–0.15 毫秒；大头在物理那一步（`_physics_process` + `move_and_slide`，挤成一团时兵与兵的碰撞最多）。不带 AI 的骨骼动作每人约 0.04 毫秒（200 人约 9 毫秒）。
- 渲染：人物模型每人约 3 次绘制调用（低画质）/ 约 6 次（中画质，多一遍影子）；Godot 导入时自动生成的网格 LOD 在兼容渲染器里生效，10 人时平均每人约 8,400 个三角面，200 人时降到约 2,800。
- 这些是云端测试机的数字：手机 CPU 可能慢 1–2 倍，电脑通常更快（估计）；本环境没有显卡，GPU 耗时要真机实测。

**预算**（D8）：同时活着、在打的士兵 ≤ 60；战斗场景每帧逻辑 ≤ 10 毫秒（网页、云端测试机）；绘制调用 ≤ 400（战场本身 ≤ 150，留 ~250 给士兵）；三角面 ≤ 50 万（`ART.md` 第八节）。

**实现思路**（B.1–B.5 细化，可能随实测调整）：
- `actors/soldier.gd`（继承 `Enemy`）：目标从「玩家」换成「最近的敌方」（玩家也是目标之一），阵营字段；`Enemy` 里直接读 `player` 的地方先抽成「当前目标」。
- `combat/battle.gd`：一场战斗的管理者——阵营与敌对关系、名额（≤ 60）与波次、空间分格查最近敌人（每 0.25 秒错开相位重选一次目标，不是每帧遍历所有人）、士气汇总与胜负判定、写旗标。
- `CombatDirector` 的攻击令牌改成**按目标分配**（每个目标最多 2 个攻击者），玩家那一份不变。
- 防挤团：兵与兵之间加简单的分离力（或 `NavigationAgent3D` 的避让，实测哪个便宜用哪个），让战场散成一对一的缠斗——挤成一团时物理开销上涨最快（测试里 50 → 100 人逻辑耗时翻倍多）。
- 降频：离玩家 25 米以外的兵感知与重新寻路降到每 0.3 秒，骨骼动作每 2 帧推进一次（`AnimationMixer` 手动推进）；倒下的兵停 AI、停动作（停在倒地最后一帧）、去碰撞。
- 影子：中画质只给 15 米内的兵投影，低画质不投影。
- 外观：士兵复用 `CharacterModel`，服装来自 A.2 的服装包（`ART.md` 7.1），阵营色用材质参数，同一阵营共用材质（少换状态）。
- 每一步都用 `army_bench` 复测 50 / 60 / 80 人，B.5 再请所有者在真机上跑一场 60 人的战斗。

**B.1 已实现（阵营与士兵对打）**，和上面的思路有三处不同（都是实测后改的）：
- `actors/enemy.gd`：「对手」抽成 `foe()`（基类永远是玩家，序章行为不变）；`_strike_player()` 改名 `_strike_target()`：对手是玩家走 `Melee.receive_hit()`，是兵走它的 `take_hit()`（返回 `"block"` / `"hit"` / `"dead"`，被挡住时出招的一方提前收招）；
  `take_hit()` 按 `info.attacker` 的位置判断正面能不能挡（没写攻击者 = 玩家，`Melee` 不写）；`last_attacker` 记最后打中自己的兵，只有玩家打倒的才扣声望（`rep_faction()`）；`transient` 的兵倒下、求饶、逃跑不写进 `GameState.dead` / `yielded`，`drops_loot = false` 的不留搜刮点；
  远处（离玩家 12 米外）兵打兵不冒飘字（Label3D 多了费绘制调用）。
- `actors/soldier.gd`（`Soldier`，继承 `Enemy`）：`side`、`battle`、`target`；开战即战斗，`_perceive()` 不打视线射线、总当作看得见对手；每 0.25 秒（相位错开）向 `Battle.pick_target()` 重挑对手，对手不能打了马上换，出招中途不换；
  友军（玩家那一边）移出组 `enemy` / `damageable`、碰撞层去掉第 4 层「可受击」，玩家的剑扫不到；头顶名字不挂、状态只在离玩家 8 米内显示。**实测两处卡死**：① 跪地求饶的兵堆在人群中间，两边都挤不过去——求饶后碰撞层清零；② 拿着攻击令牌却被人挡住够不着，一直占着令牌——2.5 秒没出招就交回令牌。仗打完了还站着的兵收手（`stand_down()`：回巡逻、原地站着），不再算「附近有敌人」。
- `combat/battle.gd`（`Battle`）：阵营、名额（`MAX_ACTIVE = 60`，多出来的排队、有人倒下 / 求饶 / 逃了再补，排队的没进场景、战斗释放时一起释放）；**没有做空间分格**：60 人以内直接遍历（每帧约 4 个兵重挑 × 60 次比较）；
  **没有加分离力或导航避让**：挑对手时被别人盯着的目标每多一人当作远 3 米（`SPREAD`）、现在的对手只「远」1 米以内就不换（`STICK`），加上按目标分配的令牌，战场自然散成一对一、二对一（测试里 20 人同时盯着 20 个不同的人）。每 0.25 秒查一次：只剩一方（玩家那一方算上玩家）就结束，发 `ended(winner)`。
- `combat/combat_director.gd`：`request(who, target)` 按目标分配令牌（每个目标最多 2 个），不写目标或目标是玩家时走原来那一份；换目标时自动交回原来那一份。
- `world/battle_arena.gd`（`?test=3`）：46 × 46 米雪地、四支火把、白带身后 1.5 米高的观战台（台阶每级 0.25 米：主角最多跨 0.3 米，正好 0.3 米时会卡住）；白带 / 黑带各 10 人（`&n=` 最多 30），剑兵与民兵七三开，罩袍按阵营上色、胸前白 / 黑布带；`main` 开局 3 秒后 `battle.start()`。
- **B.2 小队与指令**：`Battle.squad` / `add_to_squad()` / `order(o)`（`follow` / `hold` / `charge`，`ORDERS`）；`leash(s)` 给小队的兵一条「拴绳」[中心, 半径]——跟随时是玩家、7 米，坚守时是坚守点、5 米——`pick_target()` 只挑圈里的敌人（玩家也一样）；
  `post_of(s)` 是没有对手时该站的位置：跟随 → 玩家身后三人一排（排距 1.6 米），坚守 → 下令时玩家面前 2 米横排（每排 6 人）。`Soldier` 覆盖 `_patrol()` / `_combat()`：有位置、没对手就走过去站好、面朝队形方向（开打前、打完收手后也一样，所以「跟随」平时也跟着你走）。
  **实测卡住**：走向位置时正对着玩家或别的兵会撞住不动（`move_and_slide` 迎面滑不开）——0.25 秒几乎没挪动就往左或往右偏 75° 走 0.7 秒（`_check_blocked()`），加上以后 6 个人 5 秒内都站到队形里。
  头顶 ◆ 是 `Label3D`（小队最多 12 个）；`Hud.refresh_squad()` 右对齐写在右上角按钮下面；键盘动作 `order_follow` / `order_hold` / `order_charge`（1 / 2 / 3，对话打开时游戏暂停、数字键选选项，不会误下命令）；`TouchControls` 的「令」在「视角」上方，展开的三个按钮不算进 `buttons_rect()`（底部提示不跟着挪）。
- **B.3 士气、溃逃与胜负**：`Soldier.morale` / `shake()` / `break_rank()`（士气 ≤ 15 → 逃跑，或按 `yield_chance` 的一半跪地求饶）；`Soldier._enter()` 第一次进入倒下 / 求饶 / 逃跑时调 `Battle.on_fall()`（每人只算一次）：
  附近同伴慌（被吓跑的 `broke` 减半）、队长被打倒（不是跟着溃逃跑掉）时两边全队士气变化并发 `captain_down`，再 `_check_rout()`：倒下 / 求饶 / 逃跑 × 2 > `side_total()`（上了场的 + 排队的 + 没到的援军）就全体 `break_rank()`、取消这一方没到的援军、发 `routed_side`。
  `morale_tick()` 由每个兵每秒（相位错开）调一次，遍历 60 人以内的名单看 8 米内的敌我人数、`CombatDirector.count_for()` 看有没有被两个人同时打、玩家在不在 6 米内。结束判断里玩家那一方溃逃以后不再因为「玩家还站着」算站着。
  援军 `add_wave(side, soldiers, parent, delay)`：`elapsed`（游戏时间）到了就逐个 `enlist()`；没进场景的援军和排队的兵在 `Battle` 释放时一起释放。`result_flag` 结束时写 `"won"` / `"lost"`（玩家不参战时写赢家的阵营编号）。
  **实测调过一次数值**：队长倒下 −30、崩溃线 20 时，先倒一个兵、再倒队长，民兵直接崩、带着旁边的人连锁崩，整队溃逃——改成 −20、15、民兵起始 55、被吓跑的同伴影响减半；满血 10 对 10（玩家不参战）援军原定 20 秒到，4 局在 13–19 秒就以一方溃逃结束、援军常常赶不上，改成 12 秒；改后 4 局都在 13–14 秒以一方溃逃结束，赢的一方倒下 1–4 个。
  性能：网页 60 人（人物模型）`mode=battle` 逻辑 6.8 毫秒（B.1 时 7.3 毫秒，在误差内）。
- **B.4 兵种**：`enemies.json` 新增 `shield`（剑盾兵）/ `spear`（长枪兵）/ `archer`（弓手）；`Enemy` 认识两种新兵器 `spear` / `bow`，数据可选字段 `"shield": true`（`OPTIONAL_KEYS`，校验照旧拒绝别的陌生字段）。
  盾是左手一块 `BoxMesh`（`Soldier` 涂成布带色；现在每面盾一份材质，和布带一样，B.5 合并占位网格时再按阵营共用）；格挡沿用 `block_chance`（剑盾兵 0.7），重击照旧破防；`take_hit()` 遇到 `kind = "arrow"`：有盾、正对着（和近战同一个 0.4 的点积）就挡住，否则不能挡。
  长枪：`reach` 2.6（剑兵 1.8），出招时整条手臂沿前后方向收回 0.3 米、刺出 0.45 米（`_animate_reach()`），不是挥。弓手：`Soldier._archer()` 覆盖近战——离对手 5–16 米（`BOW_MIN` / `BOW_MAX`）站定，冷却 2.4 秒、拉弓 0.7 秒后 `_loose()`；太近就边退边对着他；**不申请攻击令牌**（不近身，不占「每个目标最多 2 人」的名额）。
  `combat/arrow.gd`（`Arrow`）：直线、每秒 28 米、最多飞 1.6 秒；每帧一条射线查这一段（世界 + 兵 + 玩家），射中射手的自己人就把它加进排除表继续查（最多 6 次）；射中玩家（且射手和玩家敌对）走 `Melee.receive_hit()`，`kind = "arrow"` 不触发完美格挡；伤害按射手的力量、技能走 `DamageCalc`（轻击）。准头：瞄胸口，散布 ±(0.08 + 距离 × 0.02) 米。
  动作：免费动作库没有长枪和弓（`assets/SOURCES.md`），这一步只在占位胶囊上用代码摆手臂；换人物模型（B.6）时再定动作来源。`army_bench` 的 `mode=battle` 改成和试验场同样的兵种搭配（`BattleArena.kind_for()`）。
- **B.5 60 人性能**（实测见 `TEST_REPORT.md` 2026-10-05「B.5」），和上面的思路有三处不同：
  - **先拆了一遍耗时**（`army_bench` 原生、60 人、插桩副本不入库）：每帧兵的物理约 2.4 毫秒，其中 `move_and_slide` 约 1.2 毫秒、敌人 AI 约 0.7 毫秒、军阵的挑对手 / 士气等约 0.5 毫秒；人物模型（B.6 以后）再加 1.2–1.7 毫秒骨骼动作。所以省的是碰撞移动和骨骼动作，**没有做「远处的兵感知降频」**——兵本来就不打视线射线，挑对手每 0.25 秒一次，再降省不了多少。
  - **合并占位网格**（`MeshKit.flatten()` / `flat_mat()`、`Soldier._bake_look()`）：身子底下除兵器以外的网格（罩袍、头、鼻子、布带、盾、小旗）压成一个表面，颜色写进顶点色（`vertex_color_is_srgb`，和原来的材质颜色一致；带贴图的木头用一个木色代替），兵器多个表面（剑身 + 木柄）也压成一个。每人 6–8 次绘制调用 → 2 次（中画质身子再加 1 次影子）。打中时的红光整个人一起闪（`coat_mat` 换成合并后的材质）。`Enemy.has_shield` 代替 `shield != null`（盾的网格合并后就没了）。
  - **影子没有再按人限 15 米**：月光阴影本来就只画 25 米内（`moon.directional_shadow_max_distance`），合并以后每人只多 1 次，60 人中画质 281 次已在 400 以内。
  - 站着不动、脚踩着地、上次 `move_and_slide` 以后没被挪过的兵这一帧不做 `move_and_slide`（`Enemy.rest_still`，只有 `Soldier` 打开；最多隔 `REST_MAX` = 12 帧还是做一次，脚下的地有变化也察觉得到）。**实测抓到**：只看 `is_on_floor()` 的话，被挪到半空的兵（读档、测试摆位置）一直以为踩着地、掉不下来——加了「没被挪过」这一条。
  - 跪定了（求饶、身子降到底、踩着地）的兵 `set_physics_process(false)`：跪着的不挡路（B.1 已去碰撞）、不能当对手，没有要每帧算的；倒下的本来就停了。仗打到后半段跪下的越来越多，省得越多。
  - 动作降频：`CharacterModel.set_anim_every(n)`——n > 1 时 `AnimationPlayer` 改手动推进，每 n 帧把攒下的时间一次推进；`Soldier._lod()` 每 0.25 秒按离镜头的远近设（15 米外 2，以内 1）。兵现在还是占位胶囊，只有 `army_bench` 的 `model=1` 给兵挂了人物模型（`Soldier.model`）；B.6 换人物模型时直接用上。倒下以后停在最后一帧要等 B.6 有倒地动作再做。
  - 真机基准：`?test=3&n=30&perf=1`（`main.run_battle_benchmark()`）：你不参战（`player_side = ""`）、直接开打（不自动存档）、关掉士气（不溃逃，测打得最凶的时候；手机上开着士气 60 人十来秒就溃逃完了）、军阵提示不弹；开打 3 秒后在观战台上、两军之间各测 4 秒，结果表（帧率、最慢一帧、绘制调用、逻辑耗时）写在性能浮层上。`perf_probe()` 多了 `logic_ms`：每帧从第一步物理（没有就从处理）到开始画画——引擎的 `TIME_PROCESS` 在网页上差不多是整帧时间（实测 2.8 帧时 375 毫秒），分不出逻辑和显卡，不用。
- 性能实测见 `TEST_REPORT.md` 2026-10-04「B.1」：`army_bench` 的 `mode=battle`（两边对打、玩家不参战，按游戏时间计）：网页 60 人带人物模型逻辑 7.3 毫秒、胶囊 4.7 毫秒。**占位胶囊每人约 6 次绘制调用**（身子、头、鼻子、布带、兵器，中画质再加影子），比人物模型还费，60 人中画质 566 次超预算——B.5 合并占位网格、限影子距离，B.6 换成人物模型。

### 4.11 时段与旅行地图（路线图 4.2，2026-10-08）

- **时段**（`world/daypart.gd`，`Daypart`）：清晨 `dawn` / 白天 `day` / 黄昏 `dusk` / 夜 `night`，**按剧情切换，不是自己走的时钟**（`STORY.md` 4.9）。当前时段记在 `GameState.daypart`（跟着存档走；4.2 以前的存档没有这一项，按这一章开头的时段：序章夜、第一章清晨，`Chapters.daypart_of()`）。
  - 切换的入口：进一章（`start_chapter` 用 `Chapters.LIST[n].daypart`，第一章是清晨）；走旅行地图（路线写着「到了是白天」）；对话效果 `{"daypart": "dusk"}`（对话关上后 `main.set_daypart()`：黑一下再换光，提示「到黄昏了」，减少动态效果时直接换；不重新载入场景）；对话条件 `{"daypart": "day"}` / `{"daypart": ["dawn", "day"]}`（NPC 按时段换开场白，4.6 用）；网页 `?daypart=dawn|day|dusk|night`（截图、预览，记进游戏状态，**每次打开页面只用一次**——之后读档、进章、走地图改的时段不再被它盖掉，审查发现）。
  - `Daypart.apply(main, id)` 在 `main._ready()` 搭好区域、烘焙导航以后、`apply_quality()` 以前调用；每一项都是「设成某个值」，可以重复调：环境（天色 = 远雾颜色、环境光、深度雾起止与曲线、贴地高度雾、泛光强度、对比度、饱和度）、日月光（就是原来的 `moon`：颜色、强度、角度）、贴地雾带（`fog_plane.gdshader` 的 `color`，`density` = 第一次套时记下的 `base_density` × 倍数，不会越乘越淡）。
  - **夜的预设和序章原来写死的数值一字不差**（测试对照）；开不开阴影、泛光、雾带减半仍归画质，换画质不会把时段冲掉。
  - 只管室外的剧情区域（`Daypart.affects()`）：室内（酒馆、小教堂）、灰盒测试场、训练场永远是原来的样子，`Daypart.current` 记成 `night`。
  - **窗户**：整栋房子按材质合并成一个网格（`house.gd`），不能一扇一扇关。`Daypart.set_windows()` 给亮窗的玻璃表面覆盖成暗玻璃、窗外光晕的表面覆盖成看不见的材质（`Look.hidden()`），共用的材质不改（`Look._mats` 跨场景缓存着，改了会带进室内）。白天家家不点灯；清晨按房子的种子挑约三分之一还亮着（`House` 记下 `seed`，同一栋每次结果一样）；黄昏和夜照旧。看不见的光晕表面仍算一次绘制（和夜里一样多）。
  - **夜灯**（组 `night_light`）：街灯（`StreetLamp.set_lit()`：灯、光晕藏起来，灯笼玻璃换成暗的，停掉闪烁）、墓园的三盏灯、渡口的四盏风灯、桦林门口的两盏风灯（`Daypart.mark_night_light(灯, 光晕)`）。清晨、白天灭掉，黄昏点上。营火、修士手里的灯笼不算夜灯。**灭掉的灯退出组 `light_source`**——敌人感知只看亮着的灯。墓园、渡口、桦林风灯的灯笼小方块（合并在区域网格里）白天仍是亮的颜色，那几章用到时再处理。
  - **敌人视距**：暗处（不在亮着的灯旁）的视距按时段：夜 8 米（原来的 `SIGHT_DARK`）、黄昏 12、清晨 14、白天 20（= 灯下的 `SIGHT_LIT`），蹲着照样打六折（`Enemy.sight_range()` 读 `Daypart.sight_dark()`）。军阵里的兵（`Soldier`）不走这套感知，不受影响。

### 4.13 区域边缘与地图结构（路线图 3.10 与 D10，2026-10-09）

- **地图结构**：分区（关卡式）——每块户外区域几十米见方，区域之间用门 / 路口连，过去黑 0.25 秒、重新载入（4.7b）。所有者看到渡口北头「空地里一扇门」后定 **D10 = A + B**：
  A 分区不变、把边界做实（3.10，下面）；B 第一章的鹭沼做成一张连续户外地图（4.4 起，下面「连片地图的做法」）；C 几平方公里的开放世界暂不做（网页无线程版后台加载会卡、手机浏览器内存小、内容量也撑不起来）。
- **为什么会空**（`?cam=` 逐个区域截图查出来的）：雪地只比走得到的范围大三米，夜雾 36 米才吞没，边界却在 4–10 米内看得到；出口只是一块门板，没接围栏也没有路。
- **`Edges.dress(parent, 区域矩形, 出口, 不铺的矩形, 种子)`**（`world/edges.gd`）：
  - 地面往外铺 60 米（四条，只有画面没有碰撞，比区域地面低 2 厘米；`skip` 裁掉渡口的河面）。
  - 边界外两圈白桦：近圈 1–14 米、每 2.9 米一格；远圈 18–46 米、每 7 米一格，只有树干两根枝、不投影子。网格抖动取位置（每格一棵），出口那条路两边空出来，`skip` 里不种。
  - **树用多实例画**（`MultiMeshInstance3D`）：近圈两种、远圈一种树的模型各做一份，几百棵副本随机转向、高矮。第一版逐棵拼进合并网格，光收边就 130–280 毫秒（换区域网页上要多卡半秒多），改成多实例约 2–4 毫秒。树的模型不放静态缓存（静态变量里存网格退出时报资源没释放）。
  - **按块分**：树按 48 米的块（远圈 96 米）分成几个多实例节点（一个区域 4–12 个），相邻的块轮流用近圈的两种树。一整圈一个节点的话引擎没法按视野和影子范围裁，身后、影子范围外的树都照画；分块后整块裁掉。每块每种树两次绘制（树干、枝条）。试过 24 米的块：图元少一到三成，但霜渡镇绘制调用到 390（预算 400），所以用 48 米。
  - 树的位置另记在节点的元数据 `spots` 里：无界面跑测试时引擎读不回多实例的变换（全是原点），测试按它查出口的路上没有树、块有多大。
  - **画多少树看雾和画质**（`Edges.refresh`，`main._refresh_edges()` 在换画质、换时段时调）：夜里、黄昏雾在 36 / 46 米就吞没了，远圈根本看不见，不画；清晨、白天画。低画质（触屏默认）远圈不画、近圈只画六成（`visible_instance_count`；副本顺序事先打乱，只画前一部分也是均匀稀疏的）。
  - 出口：路（踩实的雪）往外伸 30 米；`fence` 两边各 6 米木栅栏；`lantern` 门柱上一盏假灯笼（发光玻璃 + 光晕，不是实时光源，`Daypart.mark_night_light` 白天灭）；`frame` 新做门柱、横梁、小檐、地名牌（渡口北头「桦林」）。
  - 用在霜渡镇（南门：栅栏、灯笼；去墓园的小路也伸出去）、墓园（院门外的小路）、桦林（两头：栅栏，原来就有风灯）、渡口（北头新路口，南边是河）。树都不加碰撞——走不到那里，原来的看不见的围墙照旧。
- **截图参数** `?cam=x,y,z,朝向,俯仰`：把镜头放到任意位置（只在打开页面时用，不播开场），查出口和边界用。
- **连片地图的做法（4.4 起，计划）**：鹭沼是一个区域 `marsh`，按 64 米左右一块分块；每块的东西（地面、芦苇、房子、堤道、树）按离玩家远近显示 / 隐藏，雾挡住更远的；块是分帧搭的（网页无线程版不能后台加载，一帧搭一点，不卡）。导航网格按块烘焙、相邻块连起来；存档仍记位置（不记块）。旅行地图上的芦栈村、黑鹭堡是这张图上的两个出生点（`travel.json` 的 `area` 同是 `marsh`、`spawn` 不同）；客栈、堡内大厅等室内仍走门。堤道夜战（4.9）就在这张图的堤道上打。

  - `core/chapters.gd`（`Chapters`）登记每一章：名字、章节包编号（序章 `""` 在主包里，第一章 `ch1`）、探针资源（包里一定有的一个场景，`ResourceLoader.exists()` 找得到就说明内容到了）、起点。`PLAYABLE` = 做到第几章能玩了：第一章的开场（4.3）做好以前是 0，序章结束画面不出「继续」（网页 `?preview=1` 和测试里可以打开）。
  - 章节内容放在 `godot/chapters/ch1/`：**只放场景与资源，脚本留在主包**（测试检查）。`export_presets.cfg` 的 Web 预设排除 `chapters/*`，每章一个预设（`Chapter1`，`export_files` 正好列出 `chapters/ch1/` 底下的全部文件，测试检查两边一致）；`build_web.sh` 用 `--export-pack "Chapter1"` 导出。
  - `stamp_web_build.py` 把包改名成 `packs/ic-ch1-<内容哈希>.pck`，再把「编号 → 路径和大小」写进页面（`<script>window.IC_PACKS = {...}</script>`，放在引擎脚本前面）。《余烬陷落》是固定的 `packs/<编号>.pck`，包更新以后回访的玩家可能拿到旧包。
  - `core/pack_loader.gd`（`PackLoader`，改自《余烬陷落》）：内容已经在（编辑器、无头测试、这次已挂载）就不下载；网页上先看 `user://packs/` 里有没有同名的包（下载过就直接挂载，**实测第二次进只要 3–4 毫秒**），没有再 `HTTPRequest` 下载、写进 `user://`、`ProjectSettings.load_resource_pack(path, false)`，挂上以后再看一眼探针资源；同一章旧版本的包顺手删掉。`accept_gzip = false`（线上 CDN gzip 传输，浏览器已经解压过，《余烬陷落》踩过）。失败原因写成中文（超时、网络、HTTP、存不下）。
  - `ui/pack_panel.gd`（`PackPanel`）：章节名、进度条、「已下载 1.2 / 3.4 MB」（大小来自 `IC_PACKS`，gzip 传输时响应头的长度不准）；失败时写原因，「重试」「返回」。`main.ensure_chapter()` 下载时暂停游戏，点「返回」什么都不改。
  - 入口：结束画面「继续：第一章 · 黑鹭堡」→ `main.start_chapter(1)`（确保章节包 → `GameState.chapter = 1`、旗标 `ch1_started` → 霜渡镇宅邸门口，到了自动存档、先报章节名）；**读第一章的存档**（`load_game`）也先确保章节包，拿不到就不读、现在的游戏不动。`GameState.chapter` 写进存档，以前的存档没有这一项 = 序章（不用升存档版本）。
  - 第一章包里现在只有一块路牌（`chapters/ch1/road_sign.tscn`，脚本 `world/road_sign.gd` 在主包），32 KB：Godot 导出包时总会带上自动加载的脚本和项目设置的副本（挂载时 `replace_files = false`，用的还是主包里的）。
  - **已知限制**：Godot 导出的包不是逐字节可复现的，每次重新构建包的哈希都会变，回访玩家每次更新后会重新下载章节包（现在 32 KB，以后几 MB）；以后可以改成按章节内容文件算哈希。
  - 实测时抓到：网页地址带着测试参数（`?ending=`）时，「继续」之后场景重新载入，结束画面又弹了一次——`?ending=` 改成只在打开页面时生效（换区域、读档以后不再弹）。
