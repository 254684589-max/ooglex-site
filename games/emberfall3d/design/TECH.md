## 一、引擎与导出

| 项目 | 选择 | 依据 |
|---|---|---|
| 引擎 | **Godot 4.7.2**（与仓库两款 3D 游戏同版本） | 已有构建、测试、导出脚本；GDScript 无需编译工具链 |
| 渲染器 | **GL Compatibility**（WebGL 2） | Godot 网页导出只支持这一种；桌面 / 手机浏览器都能跑 |
| 网页导出 | **无线程版**（`variant/thread_support=false`） | GitHub Pages 不能设置跨源隔离响应头，线程版跑不起来；《打工》同样如此 |
| 贴图压缩 | 同时导出桌面（S3TC/BPTC）与移动（ETC2/ASTC）格式 | 沿用《打工》导出预设 |
| 语言 | GDScript（静态类型标注） | 与现有工程一致；不引入 C# / GDExtension（网页导出支持差、包体大） |

- 环境核查（2026-09-26）：本开发环境可以从 GitHub Releases 下载 Godot 4.7.2 Linux 编辑器（约 78 MB）。导出模板包 1.28 GB，但只需要其中约 10 MB 的 `web_nothreads_release.zip`：`tools/fetch_godot.py` 按字节范围只下载这一个文件（阶段 1.1 已验证）。

## 四、关键系统的实现方式

### 4.1 移动与寻路

- 点击地面：从相机发射线与地面碰撞层求交，交给 `NavigationAgent3D` 寻路；按住鼠标时每 0.15 秒刷新目标（V0.1 已验证的手感）。
- 手机摇杆：直接按方向移动，靠碰撞体贴墙滑动，不走寻路。
- 导航网格：手工区域在编辑器里预烘焙；随机地下城在生成后于运行时烘焙。**阶段 1.3 实测**（2026-09-26）：与 V0.1 同规模的一整层地下城（116 米见方、14 个房间、1155 格地面、616 格墙）在网页导出里同步烘焙 **39–42 毫秒**（无头 Chromium，527 个多边形；本机原生 34–53 毫秒），远低于 1 秒目标，运行时烘焙可行，不需要模块预烘焙。
- 导航参数必须对齐体素：半径是 `cell_size` 的整数倍（0.25 米格子 → 半径 0.5 米）、高度与攀爬是 `cell_height` 的整数倍（高 2.0 米、攀爬 0.25 米），否则引擎取整并报警告。
- 到达判定按水平距离自己算（0.15 米）：导航网格表面按格子高度量化、略高于地面，`NavigationAgent3D.is_navigation_finished()` 实测不会变 true。
- 触屏会同时产生模拟鼠标事件（`device = DEVICE_ID_EMULATION`）：玩家控制只认真正的鼠标，触屏走 ScreenTouch / ScreenDrag；虚拟摇杆认领的触点标记为已处理。

### 4.2 战斗

- 命中检测：近战用挥砍瞬间的形状查询（扇形 / 圆形），不用长期存在的 Area3D，减少物理开销；投射物用对象池，每帧射线步进。
- 伤害流水线：`攻击方数值 → DamageCalc（balance.json 系数）→ 抗性 / 护甲 → 状态效果 → HitFeedback → 死亡与掉落`，全部是纯函数或管理器调用，可以在无头模式下单元测试。
- 命中停顿：只冻结命中双方的动画和移动（局部停顿），不改全局 `Engine.time_scale`，避免影响界面和其他怪物。
- 同屏上限：活跃敌人 ≤ 60；离玩家超过 25 米的敌人降为每 0.5 秒思考一次，看不见的停止动画。

### 4.3 敌人 AI

- 状态机：待机 → 发现 → 追击 → 攻击（前摇 / 判定 / 后摇）→ 受击 → 死亡；行为组件按怪物数据组合（`monsters.json` 里写组件名和参数）。
- 群体避让：用导航代理的避让；数量太多时退化为简单的相互推开（V0.1 的做法）。
- 首领：阶段表驱动（血量阈值 → 切换招式池 + 演出），每个招式有独立的地面预警。

### 4.4 技能

- 技能是数据：`skills.json` 定义消耗、冷却、系数、形状、投射物、状态，以及两次分支强化的差异项；少数特殊技能（引导、召唤、位移）配一个小脚本。
- 三个职业的资源规则（誓火 / 热度 / 静）各写一个 `ClassKit`，统一接口：`can_cast()`、`on_cast()`、`on_hit()`、`tick()`。
- 心火觉醒与灼痕：一个共享组件；灼痕只写入存档和日志，不进入战斗公式（`GDD.md` 第 5.4 节）。

### 4.5 装备与掉落

- 直接移植 V0.1 的生成逻辑（品质判定、词缀池、命名、需求等级），数据由 `tools/port_v01_data.py` 从 `games/emberfall/play/game.js` 抽成 JSON，之后以 JSON 为准。
- 掉落表按「区域等级 + 怪物类型 + 难度」查表，概率系数放 `balance.json`。
- 物品存档只存「基础类型 + 词缀 + 数值」，不存显示文字，便于以后改名。

### 4.6 世界与关卡

- 手工区域（主城、野外）：每个区域一个场景，编辑器里摆放，**烘焙光照**（**实测**：Godot 4.7 兼容渲染器能否显示在编辑器中烘焙的光照贴图；不行就改用顶点色 + 贴图绘制的明暗）。
- 随机地下城：沿用 V0.1 的「房间 + 走廊」生成思路，改为 3D 模块拼接（墙、地、门、转角、装饰各几种变体）。随机场景不能预烘焙光照，改用：模块自带顶点色环境光遮蔽 + 火把实时点光源（受数量预算限制）+ 发光面片。
- 区域切换：进入新区域时加载对应场景，旧场景整体释放；地下城楼层在内存里只保留当前层和上一层。

### 4.7 界面

- 全部用 Godot Control 节点，按 `ART.md` 第五节的「铸铁与余烬」风格；中文字体用开源字体（SIL OFL），只打包实际用到的字符以控制体积（参考 working-life/tools/build_font.py 的做法）。
- 打开面板即暂停（`GDD.md` 第三节）；手机与电脑两套布局，按屏幕宽度与触屏能力切换。

### 4.8 存档

- 网页上 `user://` 实际存到浏览器 IndexedDB。JSON 格式，3 个栏位，每个栏位保留「当前 + 上一份」两份；读档失败回退到上一份（不用空数据覆盖有效数据）。
- 存档带 `version` 字段，读档时逐版本迁移；迁移函数有单元测试。
- 自动存档时机见 `GDD.md` 第十二节。

### 4.9 音频

- 三条总线：音乐、音效、环境声（沿用《打工》的 AudioManager 结构）。
- 浏览器要求用户交互后才能播放声音：标题画面第一次点击时再启动音频。
- 首发音效可先用代码生成或 CC0 音效库；配乐后续另议（阶段 6）。

## 五、画质与性能

### 5.1 画质分档

| 档位 | 渲染分辨率 | 实时光源 | 阴影 | 粒子 | 后处理 |
|---|---|---|---|---|---|
| 低（手机默认） | 0.75× | 主角 1 + 火把 2 | 只有主角的圆形假阴影 | 50% | 只有调色 |
| 中（默认） | 1.0× | 主角 1 + 火把 4 | 主方向光阴影（近距离） | 100% | 调色 + 暗角 + 雾 |
| 高 | 1.0×（可 1.25×） | 主角 1 + 火把 8 | 方向光 + 部分点光源阴影 | 100% | 全部 + 热浪扭曲 |

- 兼容渲染器每个物体受光数量有上限（项目设置可调，默认 8），火把布局按「同一块地面同时照到的灯 ≤ 4」设计。
- 首次启动按设备自动选档（触屏设备默认低档），玩家可在设置里改。

### 5.2 预算（与 `ART.md` 第九节一致）

| 项目 | 上限 |
|---|---|
| 典型战斗镜头绘制调用 | ≤ 600 |
| 同屏三角面 | ≤ 60 万（中档） |
| 显存中的贴图 | ≤ 512 MB（中档）/ 256 MB（低档） |
| 帧率目标 | 电脑 60 FPS；中端手机 30 FPS（低档） |

- `tests/perf_stats.tscn`（xvfb 原生渲染）与网页 `play/?perf=1`（`tools/perf_web.js`）在固定机位统计绘制调用、图元、可见物体，每个画质步骤都跑一次，写进 `TEST_REPORT.md`。
- **阶段 1.5 基线**（2026-09-26）：大厅战斗镜头绘制调用 233–254、图元 1.3–1.5 万；60 只怪物每帧更新 2.3–2.5 毫秒（本机）。详见 `TEST_REPORT.md`。
- 占位模型统一用 `core/low_poly.gd` 的低分段基本体：Godot 默认的球 / 胶囊等分段太高，1.5 实测同一镜头图元从 25.3 万降到 1.5 万。
- 不要用 `Performance.TIME_PHYSICS_PROCESS` 衡量 AI 开销：无头模式下数值陈旧（1.5 实测）；用 `EnemyBase.prof_us` 直接计时。

### 5.3 包体与加载（D1：100–300 MB）

- **基础包**：引擎 + 界面 + 共用素材 + 序章，目标 ≤ 120 MB。
- **章节包**：每章一个额外资源包，进入该章前下载并加载。**阶段 1.1 实测可行**（2026-09-26）：网页导出里用 `HTTPRequest` 下载 `packs/<id>.pck`、写入 `user://`、再 `ProjectSettings.load_resource_pack(path, false)`，在无头 Chromium（软件渲染）1280 / 768 / 360 三个宽度下均成功，6 KB 测试包用时 0.4–1.7 秒（含下载）。实现：`godot/core/pack_loader.gd`；导出：预设「ChapterTest」+ `--export-pack`。
- **章节包约定**：章节包**只放场景与资源，脚本一律留在主包**。实测中章节包里的脚本 UID 不在主包的 UID 表里，加载时会报警告（能回退到路径加载，但不干净）；把脚本移回主包后零报错。
- 加载画面显示真实的下载进度与失败重试（沿用 working-life 的 shell.html 做法）。

## 七、素材导入规范（阶段 2.2 细化）

- 模型统一用 glTF 2.0（`.glb`），1 单位 = 1 米，角色面朝 -Z。
- 命名：`类别_名称_变体`，例如 `dng_wall_straight_a`、`chr_emberguard_m`、`mon_ashcorpse`。
- 每个导入的素材在 `assets/SOURCES.md` 记一行；导出预设的 `include_filter` 把 `SOURCES.md` 打进包里（与《打工》的做法相同），许可要求署名的在游戏「制作人员」页列出。
- AI 生成的素材同样记录工具名、提示词、日期（`ART.md` 第 8.2 节）。

## 八、安全与隐私

- 纯单机，不收集任何个人数据，不发网络请求（章节包下载只访问同源静态文件）。
- 不在代码或存档里放任何密钥；云存档 / 排行榜（阶段 8）需要所有者另行审批 Cloudflare 服务。

## 九、主要技术风险

| 风险 | 影响 | 应对 | 何时验证 |
|---|---|---|---|
| 兼容渲染器画质不够「暗黑 3 观感」 | 核心目标 | 手绘感材质 + 调色 + 轮廓光 + 假光照；垂直切片由所有者拍板 | 阶段 2.3、3.4 |
| 随机地下城无法烘焙光照 | 地下城偏平 | 模块顶点色 AO + 火把实时光 + 发光面片 | 阶段 1.5、2.3 |
| 网页运行时烘焙导航网格太慢 | 进地下城卡顿 | 模块预烘焙导航后拼接 | **阶段 1.3 已验证：整层 39–42 毫秒，无需预烘焙** |
| 章节包动态加载不可行 | 首次加载过大 | 单包 + 压缩素材 | **阶段 1.1 已验证可行** |
| 手机浏览器帧率低 | 手机玩家体验差 | 低档画质、同屏敌人上限、思考频率分级 | 阶段 1.5 起每步测 |
| 素材站被网络策略拦截 | 美术进度卡住 | 所有者放行域名或手动上传素材 | 阶段 2.1 |
| 导出模板体积大、磁盘额度不够 | 无法在本环境导出 | `tools/fetch_godot.py` 只下载网页模板（约 10 MB） | **阶段 1.1 已解决** |

## 十、阶段 1 的起步清单（对应路线图 1.1–1.5）

1. 下载 Godot 4.7.2，复制并改写 working-life 的 `tools/` 与 `tests/` 框架，建空工程，导出空场景到网页，Playwright 冒烟通过。顺带**实测**：章节资源包动态加载。
2. IsoCamera：固定俯角、跟随、遮挡半透明。
3. 点击移动 + 虚拟摇杆 + 导航网格；**实测**：运行时烘焙导航网格耗时。
4. 战斗手感：一个职业（烬卫）的基础攻击 + 1 个技能，命中停顿、闪白、击退、伤害数字、震动。
5. 灰盒房间 + 3 种怪物 AI（冲锋、远程、召唤），性能基准进测试报告。

全部是灰盒（几何体占位，明确标注），不涉及美术素材。
