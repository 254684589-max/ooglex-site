# 金融终端Beta远端验收与上线门禁

本规范用于判断Ooglex金融终端当前适合继续开发、公开Beta，还是可以声明为稳定V1。门禁只读取仓库快照与GitHub Actions运行记录，不调用行情API、不改写数据、不部署网站。

## 判断对象

门禁覆盖四条生产数据管道：

| 管道 | 本地数据证据 | 远端工作流证据 |
|---|---|---|
| 宏观雷达 | `apps/macro-radar/data.json`与`health.json`中的FRED `DGS10`、FRED `DTWEXBGS`、EIA `RWTC` | `macro_radar.yml` |
| 跨资产强弱 | `apps/asset-tracker/data.json`与`health.json` | `asset_tracker.yml` |
| 全球公司榜 | `apps/companies/data.json`与`health.json` | `companies.yml` |
| 全球资产榜 | `apps/asset-ranking/data.json`与`health.json` | `asset_ranking.yml` |

终端静态配置和页面还会被检查，以确认5项演示资产、FRED免责声明、EIA来源、非投资建议及标的口径仍然清楚可见。

## 状态含义

| 状态 | 含义 | Beta决策 |
|---|---|---|
| `PASS` | 该检查项达到当前目标 | 可以继续 |
| `WARN` | 数据或产品仍有限制，但已明确标注且不构成Beta硬阻塞 | 可以上线Beta，但必须保留警告 |
| `BLOCKED` | 缺少运行证据、数据/健康错配、任务失败或存在误导风险 | 不应上线Beta |

整体状态取所有检查中的最高严重级别。报告中的`targets.beta.canLaunch`只有在没有`BLOCKED`时才为`true`。

## 本地数据门槛

### 三项官方行情

- `DGS10`必须来自FRED，数值单位为百分比，变化单位为bp；超过3个美国工作日标记`WARN`。
- `DTWEXBGS`必须来自FRED H.10，当前值、前值和涨跌幅能够互相复算；超过3个美国工作日或上游标记`stale`时为`WARN`。
- `RWTC`必须来自EIA库欣WTI现货，不能用`CL=F`近月期货替代；超过4个美国工作日或上游标记`stale`时为`WARN`。
- 来源、单位、日期、涨跌计算或标的错误，以及未来观测日期，均直接`BLOCKED`。

### 宏观雷达逐源健康

- `health.json`必须与三项发布记录交叉一致，并分别记录本轮成功、回退、不可用、最后尝试、最后成功和连续失败次数。
- 三项本轮均未刷新、健康文件时间在未来、健康/数据错配或报告超过72小时，均为`BLOCKED`。
- 72小时内只有部分来源刷新、首次迁移历史未知或最近刷新覆盖不足100%，为`WARN`。
- 观测本身仍可展示不等于更新链成功；旧值可用和任务最近失败必须同时进入报告。

### 演示数据与许可边界

当前允许以下5项在Beta中继续作为醒目标注的演示数据：标普500、纳斯达克100、道琼斯指数、黄金现货和比特币。它们使Beta状态至少为`WARN`，但只要页面和JSON均明确标注，就不单独构成Beta硬阻塞。

三大股指和黄金取得公开展示权、比特币完成合规API与署名之前，不得用来源不明或错误口径的精确数值替换演示数据。稳定V1不允许核心行情继续包含演示数据。

### 三条聚合管道

- `data.json`和`health.json`必须通过现有来源健康契约并严格对齐。
- `coverage`必须能由逐条`dataMeta`复算。
- 最近整批任务失败、健康报告时间在未来、健康/数据快照错配或报告超过72小时，均为`BLOCKED`。
- 72小时内的回退、估值、未知状态或健康历史尚未建立为`WARN`，不能被描述为完全健康。
- 旧快照即使仍可展示，也不能替代“自动更新链已经验证”的证据。

## 远端运行门槛

门禁通过GitHub Actions只读接口取得四条工作流在目标分支上的`workflow_dispatch`完成记录：

- 只接受与报告目标分支完全一致的记录。
- 只接受`completed`状态并具有明确`conclusion`的记录。
- 21:00 UTC至次日的运行按同一调度周期归组；同一周期多次重跑只采用最后一次结果。
- 最近一次周期必须成功且不得早于48小时。
- Beta要求四条工作流各自至少连续成功3个日更周期。
- 稳定V1要求四条工作流各自至少连续成功7个日更周期。
- 令牌、API或运行记录不可用时，不猜测成功，直接输出`BLOCKED`。

运行证据只保存必要的时间、结论、分支、提交和运行链接。GitHub临时令牌只放在请求头中，不进入命令参数、报告或日志。

## Beta与稳定V1

| 条件 | 公开Beta | 稳定V1 |
|---|---:|---:|
| 无`BLOCKED`检查项 | 必须 | 必须 |
| 明确标注的演示资产 | 允许，状态为`WARN` | 不允许 |
| 四条工作流连续成功 | 至少3个周期 | 至少7个周期 |
| 三项官方行情过期 | 可`WARN`观察，但不冒充新鲜 | 必须恢复为`PASS` |
| 宏观/聚合管道降级或历史待建立 | 可`WARN`观察 | 必须恢复为`PASS` |

稳定V1状态单独保存在`targets.stableV1`，不会因为Beta允许演示数据而被错误放宽。

## 自动报告

`.github/workflows/finance_terminal_beta_gate.yml`每日14:17 UTC运行，也支持手动触发。它具有且仅具有：

- `actions: read`
- `contents: read`

工作流生成：

- `readiness.json`：供机器读取和后续监控。
- `readiness.md`：写入GitHub Actions运行摘要，便于人工查看。

两份报告作为Artifact保留14天，不提交进Git历史。报告状态为`BLOCKED`时，观察任务仍上传证据；需要在正式发布流程中强制阻断时，可以显式使用脚本的`--fail-on-blocked`选项。

## 开发分支资格验收

`.github/workflows/finance_terminal_v1_qualification.yml`用于建立上述远端证据，不替代门禁结论：

- 只允许`agent/finance-terminal-*`开发分支，禁止默认生产分支。
- 第一波同时启动宏观雷达、跨资产与公司榜，任一失败不会取消其他独立管道。
- 全球资产榜仅在公司榜成功后运行。
- 数据任务完成后重新读取开发分支最新提交，运行完整质量与真实浏览器回归，再生成Beta和稳定V1报告。
- 工作流只拥有Actions调度权限和仓库内容只读权限；具体数据提交仍由四条既有工作流各自按路径所有权完成。
- 不合并`main`、不创建发布、不触发Pages或其他部署。

资格工作流自身成功只表示“本轮四条管道均成功并生成了最新门禁报告”。Beta仍需3个不同日更周期，稳定V1仍需7个周期且核心行情不得包含演示数据。

## 页面状态与故障反馈

金融终端页面会直接读取四份`health.json`并展示四张“Beta数据运行状态”卡片。页面只显示仓库内最近健康快照，包括可用/新鲜/已验证覆盖、最后尝试与成功、连续失败和旧快照保留；报告超过72小时显示`STALE`，健康/数据错配或单份文件不可用显示`UNKNOWN`。

这些卡片不读取GitHub Actions历史，因此不能替代本门禁的3/7周期证据。页面提供只读门禁入口和结构化数据问题表单；反馈只允许提交可公开复核的信息，不应包含API密钥、令牌、账号、持仓或其他敏感资料。故障分诊、四管道恢复顺序和关闭标准见`docs/FINANCE_TERMINAL_OPERATIONS_RUNBOOK.md`。

## 当前迁移状态

首次引入宏观逐源健康时，旧文件无法证明DGS10、DTWEXBGS与RWTC此前每次任务的结果，因此迁移状态明确为`unknown`；仓库中的四份健康报告也均已超过72小时，且开发分支尚无三次远端日更证据，因此预期结果是`BLOCKED`。这不是脚本失败，而是准确说明生产运行闭环尚未建立。

下一步应在包含全部开发提交的远端分支上运行资格验收并观察至少3个日更周期；只有报告不再含`BLOCKED`，才进入公开Beta评审。稳定V1还必须累计7个周期并解决5项演示行情的数据许可与接入。

本门禁是工程与产品发布检查，不构成数据授权或法律意见。外部来源条款变化后仍需重新核查。
