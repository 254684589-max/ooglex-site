# 金融终端Beta远端验收与上线门禁

本规范用于判断Ooglex金融终端当前适合继续开发、公开Beta，还是可以声明为稳定V1。门禁只读取仓库快照与GitHub Actions运行记录，不调用行情API、不改写数据、不部署网站。

## 判断对象

门禁覆盖四条生产数据管道：

| 管道 | 本地数据证据 | 远端工作流证据 |
|---|---|---|
| 宏观雷达 | `apps/macro-radar/data.json`与`health.json`中的FRED `DGS10`、FRED `DTWEXBGS`、EIA `RWTC` | `macro_radar.yml` |
| 跨资产强弱 | `apps/asset-tracker/data.json`与`health.json` | `asset_tracker.yml` |
| 全球公司榜 | `apps/companies/data.json`与`health.json` | `companies.yml` |
| 全球资产榜 | `apps/asset-ranking/data.json`与`health.json` | `asset_ranking.yml` |

终端静态配置和页面还会被检查，以确认4项TradingView免费ETF代理、零演示数值、FRED免责声明、EIA与CoinGecko来源、BTC/USD降级口径、非投资建议及标的口径仍然清楚可见。

## 状态含义

| 状态 | 含义 | Beta决策 |
|---|---|---|
| `PASS` | 该检查项达到当前目标 | 可以继续 |
| `WARN` | 数据或产品仍有限制，但已明确标注且不构成Beta硬阻塞 | 可以上线Beta，但必须保留警告 |
| `BLOCKED` | 缺少运行证据、数据/健康错配、任务失败或存在误导风险 | 不应上线Beta |

整体状态取所有检查中的最高严重级别。报告中的`targets.beta.canLaunch`只有在没有`BLOCKED`时才为`true`。

## 本地数据门槛

### 四项真实行情

- `DGS10`必须来自FRED，数值单位为百分比，变化单位为bp；超过3个美国工作日标记`WARN`。
- `DTWEXBGS`必须来自FRED H.10，当前值、前值和涨跌幅能够互相复算；超过3个美国工作日或上游标记`stale`时为`WARN`。
- `RWTC`必须来自EIA库欣WTI现货，不能用`CL=F`近月期货替代；超过4个美国工作日或上游标记`stale`时为`WARN`。
- `BTC/USD`必须复用全球资产榜中唯一的Bitcoin/BTC记录：CoinGecko本轮日度快照为`PASS`；Yahoo `BTC-USD`同标的降级必须显示“较前收盘”并为`WARN`；保留旧快照或超过36小时同样为`WARN`。
- BTC/USD不得读取静态估值、未知或不可用记录；逐条更新时间、行情时点、正数价格、涨跌范围、CoinGecko署名或Yahoo降级披露任一无效均为`BLOCKED`。
- BTC/USD还必须与资产榜`health.json`中的逐源证据同批对齐：CoinGecko或Yahoo来源计数、来源状态和最后成功时间任一缺失或错配均为`BLOCKED`；健康报告超过72小时或最近整批失败为`WARN`，不会把仍可读取的旧价格描述为更新链健康。
- 来源、单位、日期、涨跌计算或标的错误，以及未来观测日期，均直接`BLOCKED`。

### 宏观雷达逐源健康

- `health.json`必须与三项发布记录交叉一致，并分别记录本轮成功、回退、不可用、最后尝试、最后成功和连续失败次数。
- 三项本轮均未刷新、健康文件时间在未来、健康/数据错配或报告超过72小时，均为`BLOCKED`。
- 72小时内只有部分来源刷新、首次迁移历史未知或最近刷新覆盖不足100%，为`WARN`。
- 观测本身仍可展示不等于更新链成功；旧值可用和任务最近失败必须同时进入报告。

### 免费代理与公开展示边界

`SPY`、`QQQ`、`DIA`与`GLD`分别作为`SPX`、`NDX`、`DJIA`与`LBMA Gold Price PM`的ETF代理，通过TradingView官方免费Web Component展示。四项均为`demo: false`，但必须明确显示代理代码、原目标和“不是同一标的”的边界。

Ooglex不得抓取、导出、缓存或再分发组件中的原始行情，不得把组件值写入仓库JSON，也不得用免费API读取权冒充公开展示权。组件最多等待8秒完成Custom Element注册，再逐卡确认元素已连接、已定义且具有非空布局；只有完成宿主挂载才显示组件。宿主挂载仍不证明报价已渲染、数据新鲜或市场开市。页面分别说明加载超时、注册失败、浏览器验证不可用与宿主挂载异常；任何失败都只显示TradingView官方标的链接，不用缓存值或演示值顶替，脚本晚到注册时允许自动恢复。BTC/USD仍复用现有免密钥资产榜更新链并完成页面署名。

`apps/finance-terminal/market-source-readiness.json`逐项保存原目标、选定ETF、TradingView代码、免费非商业范围和禁止原始数据存储边界。上线门禁复算4项代理、提供方脚本白名单、零密钥、零收费源与零本地行情值；任何代理冒充原标的、改成抓取/API交付或加入仓库数值都会`BLOCKED`。

每次Chrome资格检查使用与生产页面相同的完整8秒注册窗口，在360、768和1280像素分别记录SPY、QQQ、DIA与GLD的`mounted / unavailable`状态与受控原因，并输出`finance-terminal-browser-evidence.json`、同内容的人类可读Markdown摘要和对应截图Artifact。证据逐项核对登记的TradingView官方标的链接，并复算回退区域仅在`unavailable`时可见、宿主`mounted`时隐藏；它不主动访问外链。证据还通过Chrome DevTools Network事件只观察白名单脚本`tv-mini-chart.js`是否请求、收到受控HTTP响应、使用缓存、被阻断或仍在等待；传输失败只归类为`dns / tls / connection / timeout / blocked / other`，不保存原始错误文本、响应正文、任意控制台文本或其他网络请求。逐视口关联诊断区分脚本传输失败、响应等待、脚本成功但组件注册超时、浏览器运行时不可用、部分宿主挂载和宿主验证失败。机器证据只含固定脚本URL、传输状态、受控失败分类、HTTP状态码、缓存布尔值、代理代码、宿主状态、官方回退URL/可见性和受控诊断，不读取或保存组件报价；它用于跨日复核第三方组件可用性与官方链接回退，不会替代或增加四条数据工作流的3/7成功周期。普通快速回归可以使用短超时，但不得被保存为稳定V1运行证据。

只读质量工作流另从目标开发分支最近14天的代理Artifact生成最多7周期趋势，按21:00 UTC边界将同周期重跑折叠为最新证据。趋势只保留脚本状态、受控失败分类、宿主/回退计数和诊断计数；不保留逐卡行情或原始网络错误。历史API失败必须标记`partial`并保留当前真实周期，不能伪造跨日可用性，也不能被计入核心管道稳定V1资格。

趋势运维评估使用固定两周期阈值：连续两周期三档脚本加载且12个宿主观测全部挂载才为`HEALTHY`；单周期证据、部分挂载或告警后的首次恢复为`WATCH`；连续两周期脚本传输失败或12/12全回退为`WARN`；收集不完整为`UNKNOWN`。评估不宣称报价渲染、新鲜度或开市状态，也不改变核心管道3/7与7/7计数；统一上线时应单独审阅其最新状态。

稳定V1资格工作流在四条核心管道完成并重新检出最新开发分支后，使用最终360/768/1280像素浏览器证据重建同一趋势和评估，将JSON、Markdown与截图一起保留14天，并把Markdown加入运行摘要。趋势历史只读取质量工作流的固定前缀Artifact，稳定V1自身的重复运行不会被再次作为历史源计数。

### 三条聚合管道

- `data.json`和`health.json`必须通过现有来源健康契约并严格对齐。
- `coverage`必须能由逐条`dataMeta`复算。
- 最近整批任务失败、健康报告时间在未来、健康/数据快照错配或报告超过72小时，均为`BLOCKED`。
- 72小时内的动态回退、未知、不可用、未登记`partial`路径或健康历史尚未建立为`WARN`，不能被描述为完全健康。
- 已登记慢频估值可为`ok/partial`，但必须使用`estimate`模式及慢频/不定期频率；当全部动态记录为正常行情或已登记市值代理、慢变量也完整披露时，合法估值本身不再制造`WARN`。动态失败仍单独告警，不能用估值覆盖率抵消。
- 旧快照即使仍可展示，也不能替代“自动更新链已经验证”的证据。

## 远端运行门槛

门禁通过GitHub Actions只读接口取得四条工作流在目标分支上的`workflow_dispatch`完成记录：

- 只接受与报告目标分支完全一致的记录。
- 只接受`completed`状态并具有明确`conclusion`的记录。
- 21:00 UTC至次日的运行按同一调度周期归组；同一周期多次重跑只采用最后一次结果。
- 最近一次周期必须成功且不得早于48小时。
- Beta要求四条工作流各自至少连续成功3个日更周期。
- 稳定V1要求四条工作流各自至少连续成功7个日更周期。
- 令牌、API或运行记录不可用时，不猜测成功，直接输出`BLOCKED`。

运行证据只保存必要的时间、结论、分支、提交和运行链接。GitHub临时令牌只放在请求头中，不进入命令参数、报告或日志。

## Beta与稳定V1

| 条件 | 公开Beta | 稳定V1 |
|---|---:|---:|
| 无`BLOCKED`检查项 | 必须 | 必须 |
| 明确标注的演示资产 | 允许，状态为`WARN` | 不允许 |
| 四条工作流连续成功 | 至少3个周期 | 至少7个周期 |
| 四项真实行情过期或降级 | 可`WARN`观察，但不冒充新鲜 | 必须恢复为`PASS` |
| 宏观/聚合管道降级或历史待建立 | 可`WARN`观察 | 必须恢复为`PASS` |

稳定V1状态单独保存在`targets.stableV1`，不会因为Beta允许演示数据而被错误放宽。

## 自动报告

`.github/workflows/finance_terminal_beta_gate.yml`每日14:17 UTC运行，也支持手动触发。它具有且仅具有：

- `actions: read`
- `contents: read`

工作流生成：

- `readiness.json`：供机器读取和后续监控。
- `readiness.md`：写入GitHub Actions运行摘要，便于人工查看。

两份报告作为Artifact保留14天，不提交进Git历史。报告状态为`BLOCKED`时，观察任务仍上传证据；需要在正式发布流程中强制阻断时，可以显式使用脚本的`--fail-on-blocked`选项。

## 开发分支资格验收

`.github/workflows/finance_terminal_v1_qualification.yml`用于建立上述远端证据，不替代门禁结论：

- 只允许`agent/finance-terminal-*`开发分支，禁止默认生产分支。
- 第一波同时启动宏观雷达、跨资产与公司榜，任一失败不会取消其他独立管道。
- 全球资产榜仅在公司榜成功后运行。
- 数据任务完成后重新读取开发分支最新提交，运行完整质量与真实浏览器回归，再生成Beta和稳定V1报告。
- 完整校验通过后，把门禁报告压缩为`apps/finance-terminal/readiness.json`静态证据；只提交这一份文件，且同一日更周期内结论未变时不产生重复提交。
- 工作流拥有Actions调度与证据快照写入权限；具体行情数据仍由四条既有工作流各自按路径所有权完成，资格流程不得暂存或改写其他文件。
- 不合并`main`、不创建发布、不触发Pages或其他部署。

资格工作流自身成功只表示“本轮四条管道均成功并生成了最新门禁报告”。Beta仍需3个不同日更周期，稳定V1仍需7个周期且核心行情不得包含演示数据。

开发分支尚未进入默认分支时，GitHub的定时工作流不会自动从该分支执行。为持续建立真实观察证据，`.github/finance-terminal-v1-cycle.json`可由受控外部任务在21:00 UTC之后每天最多更新一次；其推送只触发上述开发分支资格工作流。标记本身不计入成功周期，门禁仍只统计四条真实数据工作流的`workflow_dispatch`完成记录，并按21:00 UTC边界去重。同周期标记不得重复更新，达到7/7后应停止触发。

## 辅助来源资格验收

`.github/workflows/finance_terminal_supporting_qualification.yml`并行触发CNN Fear & Greed与OFR两条独立工作流，用于把迁移`UNKNOWN`转为本轮真实的成功、回退或失败证据。它同样只允许`agent/finance-terminal-*`开发分支，并在取数后重新读取最新分支，验证四个辅助来源健康契约、失败保留、路径治理和三档页面回归。

辅助资格不属于上表四条核心管道的连续周期门槛：同一天或不同日期运行CNN/OFR都不会增加Beta 3周期或稳定V1 7周期计数。其作用是阻止页面把未知更新链误写为健康，并确保辅助来源失败时仍保留最后有效快照和明确状态。

辅助资格完成四源刷新和最终三档页面检查后，也生成同格式代理趋势与运维评估并写入运行摘要；历史仍只来自质量工作流固定前缀Artifact，辅助资格自身的运行不会重复进入趋势。该证据用于确认辅助数据更新后没有破坏组件回退，不扩大核心资格口径。

## 页面状态与故障反馈

金融终端页面会直接读取四份`health.json`并展示四张“稳定V1运行证据”卡片。每张卡把两类信号分开显示：仓库内最近健康快照包含可用/新鲜/已验证覆盖、最后尝试与成功、连续失败和旧快照保留；`readiness.json`则只显示对应远端任务的连续成功周期、最近周期和可复核运行链接。

页面不会从浏览器调用GitHub或行情API；静态证据只能由完整门禁报告生成，结构、分支、工作流身份、3/7门槛和汇总均需复算。证据超过72小时显示`STALE`，结构损坏或文件不可用显示`UNKNOWN`，不会猜测成功。页面提供只读门禁入口和结构化数据问题表单；反馈只允许提交可公开复核的信息，不应包含API密钥、令牌、账号、持仓或其他敏感资料。故障分诊、四管道恢复顺序和关闭标准见`docs/FINANCE_TERMINAL_OPERATIONS_RUNBOOK.md`。

## 当前迁移状态

开发分支资格运行已成功完成四条核心管道：宏观与三条聚合健康历史均为真实`tracked`；DGS10、DTWEXBGS与RWTC均保留最多8项可追溯官方观测。BTC/USD读取同一资产榜资格管道中的逐条CoinGecko/Yahoo来源契约，不另造成功周期。仓库当前`readiness.json`生成于2026-08-14，四条工作流均为3/7个独立成功日更周期；公开Beta门槛已满足，稳定V1门禁继续为`BLOCKED`，这是最后一次已完成资格运行的准确结论，不从日历日期推测未发生的成功周期。

下一步应继续在同一完整开发分支累计4个不同UTC日的成功周期至7/7；同周期重跑不得重复计数。四项演示行情与精确基准许可不再是当前阻塞，但仍需观察TradingView免费组件的跨日可用性与失败回退。

本门禁是工程与产品发布检查，不构成数据授权或法律意见。外部来源条款变化后仍需重新核查。
