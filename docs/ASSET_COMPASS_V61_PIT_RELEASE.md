# Ooglex V61｜历史首次发布（PIT）证据链合规审计

本次目标：阻止把观测日期、GitHub first-seen 时间、FRED最新修订数据、ALFRED日期当作官方“首次发布可得时刻”。沿用 V50 的14项宏观来源参考登记、V59六资产研究来源及V60收益核算规则，建立历史发布事件的严格验证口径。

## 已实现

1. 单笔候选发布记录必须明确：series ID、观测期、官方发布UTC时间（含时区）、发布文档ID、原始字节SHA256、HTTPS来源、原始文件格式、指标单位和真实数值。未提供不能假设为0或以抓取时间填充。
2. 历史修订必须按实际公布时间严格递增，禁止同时间重复、未来发布、原始记录与修订含混。
3. 对指定决策时刻只允许看“候选时间线”中该时刻以前的记录，**即便可以计算候选as-of值，也仍不属于已认证PIT**，因为字段只是提交者自述，还缺独立机构档案核验。
4. V50登记的14个指标仍然全部为参考链接而非原始首发档案。V60与V59报告中0/6总回报、0/6评分和0历史PIT状态被直接交叉验证。生成公开 `data/asset-compass-pit-admission-v61.json` 仅含状态与原始报告SHA，不发布原始版权受限数据。

## 重要区别

- 观测日期：统计的是哪个月份或交易日；
- 官方首发时刻：该具体版本**首次对市场公开**的准确UTC可得时刻，可能比观测日期晚一天或数周；
- revision：同一观测期在之后被重新公布的真实新值，之前的交易决策不得看见；
- 系统首次获取时间：证明系统何时抓到，但不能倒推官方原始发布日期；
- 仅有FRED/ALFRED最新修订值及vintage日期，不足以证明历史日内真实可得时刻或再分发许可。
