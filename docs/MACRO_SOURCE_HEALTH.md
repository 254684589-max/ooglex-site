# 宏观雷达官方序列健康与恢复规范

本规范覆盖宏观雷达中直接供Ooglex金融终端使用的三项官方日频序列。行情快照保存在`apps/macro-radar/data.json`，最近任务证据单独保存在`apps/macro-radar/health.json`。两者分开后，页面可以继续展示明确标记的最后有效值，同时质量检查不会把保留快照误判为本轮成功。

## 覆盖范围

| 序列 | 官方来源 | 页面口径 | 变化口径 | 过期阈值 |
|---|---|---|---|---:|
| `DGS10` | FRED H.15 | 美国10年期国债收益率，百分比 | 相对上一观测值，bp | 3个美国工作日 |
| `DTWEXBGS` | FRED H.10 | 美联储名义广义美元指数 | 相对上一观测值，百分比 | 3个美国工作日 |
| `RWTC` | U.S. EIA | Cushing, OK WTI Spot Price FOB，美元/桶 | 相对上一观测值，百分比 | 4个美国工作日 |

现货、期货、ETF和其他指数不得静默替代上述序列。`RWTC`失败时尤其不能改用`CL=F`近月期货冒充现货。

`RWTC`先尝试EIA API v2；`EIA_API_KEY`缺失或API失败时，改读EIA官方`RWTCD.htm`日频历史表。公开历史页只在标题、单位、周起止日期和数值结构全部通过校验时发布，并在记录中披露实际访问路径。两条路径仍属于同一官方来源，不增加虚假的供应商冗余。

RWTC成功刷新后，`data.json`与`health.json`同时保留本轮实际访问路径：`EIA API v2`或`EIA public history page`。金融终端在WTI卡片的`UPDATE HEALTH`中显示“API v2”或“官方历史页”；旧快照没有这项证据时显示“待记录”，但不会伪造路径。未登记的镜像、期货或其他标的会被健康校验与上线门禁拒绝。

## 逐源状态

每个来源分别记录：

- `mode`：`market`、`fallback`、`unavailable`或`unknown`。
- `lastAttemptAt`：最近真实请求时间。
- `lastSuccessfulAt`：最后一次取得可发布观测的时间；失败时不得改写。
- `consecutiveFailures`：从健康契约启用后的连续失败次数。
- `snapshotPreserved`：本轮失败时是否保留了该来源的最后有效值。
- `asOf`与`publishedUpdatedAt`：当前发布观测的数据日和成功更新时间。
- `maxBusinessDays`：该序列自己的过期阈值，不能用一个自然日阈值覆盖全部来源。

语义如下：

| 本轮结果 | 有历史有效值 | `mode` | 来源状态 | 页面行为 |
|---|---:|---|---|---|
| 成功 | 任意 | `market` | `healthy` | 使用新观测，并从0重新计数失败次数 |
| 失败 | 是 | `fallback` | `degraded` | 保留旧值，显示`STALE`，记录失败尝试 |
| 失败 | 否 | `unavailable` | `failed` | 隐藏数值，显示错误状态 |
| 首次迁移、历史不可追溯 | 是或否 | `unknown` | `unknown` | 不推断此前成功或失败次数 |

三项全部成功时管道为`healthy`；至少一项成功时为`degraded`；三项本轮均未刷新时为`failed`。即使`failed`时仍有旧值可展示，也不代表自动更新链健康。

## 金融终端卡片级展示

金融终端在`DGS10`、`DTWEXBGS`和`RWTC`三张官方行情卡片内分别显示`UPDATE HEALTH`，逐源展示本轮刷新或回退、连续失败、最近尝试、最后成功和旧值保留。该状态与卡片的观测日期、数值过期状态分开：观测仍可展示不代表自动更新任务健康，健康报告正常也不代表官方来源当天一定发布了新观测。

卡片适配器会交叉校验对应序列的ID、提供方、单位、观测日期、发布成功时间和`health.json`字段。单个序列的健康字段损坏或错配时，只把该序列的健康栏降为`UNKNOWN`；仍可验证的行情数值继续按自身状态展示，另外两项官方序列不受影响。健康证据超过72小时统一显示`STALE`，迁移历史在首次真实远端运行前继续显示“历史待建立”。

## 最近观测窗口

三项官方记录在`data.json`中保存最多8个按日期严格递增的`observations`，每项只包含官方观测日`asOf`与数值`value`。页面使用该窗口绘制卡片内的最近走势，并同时显示窗口起止日期、点数和区间变化：

- `DGS10`区间变化使用基点（bp），由首末收益率之差乘以100复算。
- `DTWEXBGS`与`RWTC`区间变化使用百分比，由窗口首末值复算。
- 窗口末项必须与卡片当前`asOf`和`price`一致；日期倒序、重复、非正数、超过8项或末值错配均视为无效。
- 成功刷新时使用本轮官方响应重建窗口；失败回退时完整保留上次有效窗口，不以空数组、默认值或演示走势覆盖。
- 旧快照只迁移能由现有字段证明的观测。当前`DGS10`前值日期不可追溯，因此只保留1个有日期的真实点并提示等待刷新；`DTWEXBGS`与`RWTC`各保留2个已知日期的官方点。

观测窗口只提供近期上下文，不代表盘中走势，也不改变各序列的日频、发布延迟和过期判定。

## 恢复顺序

1. 每个官方接口在自身内部重试，不切换到错误标的；RWTC API失败后只允许尝试同一EIA官方历史页。
2. 单一序列失败时只保留该序列最后有效观测，并保留原成功时间。
3. 没有历史有效值时写入明确的不可用状态，不写零值、默认值或演示值。
4. `health.json`仍更新失败时间与次数；旧行情值不能覆盖本轮失败证据。
5. 下一次成功时仅重置对应来源的失败次数；其他来源继续保留自身状态。

## 更新任务与Git历史治理

`macro_radar.yml`使用独立并发组，生成前同步目标分支，并只允许提交：

- `apps/macro-radar/data.json`
- `apps/macro-radar/health.json`
- `apps/macro-radar/history.json`

页面、脚本或其他路径被生成任务改动时，路径守卫会在提交前阻断。生成结果与仓库一致时跳过提交和推送。逐次来源诊断和路径诊断只作为14天GitHub Actions Artifact保存；Git仓库仅保留页面所需的最新快照。

FRED与EIA密钥仅从GitHub Actions Secrets注入并通过请求参数对象传递。EIA公开历史页不接收密钥。异常日志只输出错误类型和必要的HTTP状态，不输出包含密钥的完整请求URL。

## 上线门禁

Beta门禁同时检查三项观测本身与`health.json`：

- 来源、标的、单位、数值、日期或涨跌复算错误：`BLOCKED`。
- 三项最近尝试均失败：`BLOCKED`。
- 健康文件与发布快照不一致或超过72小时：`BLOCKED`。
- 72小时内部分来源回退、覆盖不足或迁移历史未知：`WARN`。
- 三项最近刷新、健康契约一致且报告未过期：`PASS`。

观测日期过期与更新任务失败是两种不同证据：前者说明数据发布节奏，后者说明Ooglex更新链运行状态，报告必须分别展示。

## 当前迁移状态

首次迁移快照中的三项历史运行结果无法从旧文件完整追溯，因此`historyStatus`为`migrated`、逐源`mode`为`unknown`、连续失败次数为`null`。第一次真实远端运行后切换为`tracked`，从该次结果开始准确计数。

本规范不改变外部数据授权结论，也不构成FRED、EIA或其他提供方对Ooglex的认可。
