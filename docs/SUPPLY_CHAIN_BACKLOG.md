### 横轴：27 条一级产业链

纵向 12 个环节回答「在链上的哪一层」，回答不了「在**哪条链**上」——只分层不分链，
半导体设备和农机会落在同一格里看着像邻居，其实一辈子不发生关系。

`scripts/supply-chain/sic_chains.py` 用**同一个输入**（公司申报的四位 SIC 码）
给出横轴：27 条一级产业链，495 家全部有归属（未归类 0），其中 118 家同时在多条
链上——SIC 3533 油气田机械本来就既在油气链也在工业机械链，硬压成一条才是失真。

页面顶部一行链筛选。选中一条链后，它没覆盖到的环节**照样画出来并标空**：
半导体链 21 家只落在 3 个环节上（零部件 18 / 资本设备 1 / 整机 2），
上游的硅和下游的服务器都是空的——那正是「公司池只有标普 500」的直接后果，
藏起来会让人以为这条链本来就这么短。

**链是分类，不是边。** 选中一条链只是把公司筛出来，不声称同链两家之间有供应关系。
这条界线与全板块一致：框架与分类可以按行业通识建（那是定义），
公司之间的关系必须有可核验的原始出处。

### 链间上下游：77 条

横轴有了链，还缺「链与链之间谁供给谁」。`sic_chains.py` 的 `CHAIN_LINKS`
给出 77 条有向连线，每条写清**流动的是什么**——只画箭头等于没说话：

    化工与新材料 → 半导体   电子特气、光刻胶、CMP 抛光液、湿电子化学品
    工业机械     → 半导体   光刻、刻蚀、沉积、量测与封测设备
    半导体       → 计算硬件 处理器、存储、加速卡
    环保与循环   → 采矿与金属 再生金属回炉，与原生矿并行供料

两条规矩：**只连直接的一跳且构成对方主要投入**（石油→化工→合成纤维→服装
逐跳连，不从石油直连服装，否则画出来是一团糊）；**横跨全链的使能链不逐条连**
（金融、地产、商业服务、物流四条标为 cross-cutting，页面写明原因，
而不是留一块没有解释的空白）。

实物链是**闭环**：消费、电子、报废车、建筑垃圾进环保链，再生金属与再生浆
回到采矿与化工。只画一半等于说回收出来的东西凭空产生。

**这是框架，不是边。** 与 edges/ 里那两万条严格分开：数据里是 `chainLinks`
而非 `edges`，每条自报 `basis: "framework"`，发布契约硬性禁止它携带
sourceType／url／docDate，两端出现公司代码即中止。页面上是虚线块 + 「产业结构
框架」标签 + 一句「与本页那两万条不是一回事」。

#### 这一段错了两次，都是靠打印结果发现的

一、第一版直接对全图松弛，算出 **241 层、30 条回流边**。实物链有环
   （采矿→化工→…→环保→采矿），松弛在环里一圈圈往上顶到迭代上限。
   层数比链数还多十倍，页面照画不会报错。
二、第二版改成深度优先自动找回边，它按遍历顺序剪：把「采矿 → 化工」判成回流，
   **采矿被排到第 5 层、排在半导体下面**。拓扑上没错，语义上荒唐。

结论：**剪哪条边是语义问题，不是图论问题。** 改为在 `COUNTERFLOW` 里逐条写死
并写清理由，剪不干净就抛错不给层次。第三个环（采矿→化工→建筑→电力→采矿）
就是这个抛错逼出来的——四条边全是真的，我起初没看见它们首尾相接。

六条逆向边：三条回收料返上游、一条芯片回流设备厂、两条资本形成
（建电厂电网、采矿冶炼设备）与持续外供方向相反。页面上标「逆向」，
不标的话读者会以为分层排错了。

### 上游重叠：第一条公司 ↔ 公司的关系

在此之前，图上只有公司 → 冶炼厂，一条公司 ↔ 公司都没有。这一轮补上，而且它是
**两份原始申报的直接交集**，不含推断：

    英伟达那份申报里列了 A.L.M.T. Corp.
    超微那份申报里也列了 A.L.M.T. Corp.
    ⇒ 两家的名单里出现了同一家冶炼厂

90 家有名单的公司之间共 **1,914 对**有重叠。英伟达与 48 家有重叠，最多的是
超微 236 家（对方名单 251 家）、安费诺 228 家（对方 698 家）——两边的总数都要给，
只说「重叠 236 家」看不出这是多是少。

**它不表示两家之间有业务往来、供货或合作。** 它表示上游冶炼环节的共同暴露：
同一家冶炼厂一旦出事，两家的名单都会被牵动。页面上这句话是硬断言守着的。

口径**只会少算不会多算**：登记表里 868 条只有名字，各家写法不一，
同一家厂被写成两条时两家公司就不会被算作重叠。方向是确定的。

### 同一轮暴露并修好的一个真缺陷

力拓与壳牌报的是 13q-1 资源开采付款，却被判成「有申报但没列名单」。原因是旧规则
「正文出现矿产词就判冲突矿产」：**力拓有铝冶炼厂、壳牌有炼油厂**，smelter 与
refiner 是它们的业务词。而矿业与能源公司正是 13q-1 申报的主力，147 家外国发行人里
加拿大金矿与石油巨头占很大比例，不修就会成片说错话。

改了三版，每一版都靠看真实输出才发现错：

1. 只看用词 → 力拓、壳牌判错
2. 加 XBRL 结构判据 → 壳牌好了，力拓没好（它排在最前的是张 XBRL 渲染表，
   一个特征词都没有；说明报哪一套的在另一份文件里）
3. 改用 Form SD 的**条目标题** + 把取到的几份合起来判 → 力拓好了，
   却把康菲那一档的四家推了回去

第 4 版先给判据加了「把命中的特征打出来」，一跑就看清了：13q-1 申报人的文件里
两个条目标题**同时出现**（封面模板把两个都印出来），而 13p-1 申报人不会去**填**
Item 2.01。所以两个都出现时判资源开采。22 份真申报逐份核对，全部归位。

教训与前几轮同一条：**改对规则没有一次是靠自动结论，全靠打印原始数据。**
这次把「打印依据」做进了判据本身（`disclosure_evidence()`），下次不必再加一轮日志。

抠出来的（卡在 `Gold (Au)` 的元素符号上）。至少还有三种情况：

- [x] **申报的是资源开采付款不是冲突矿产** — 13q-1 与 13p-1 是两套互不相干的
      披露，康菲、纽蒙特属于后者，那套披露里没有冶炼厂这个概念。已单列一档，
      不再算进「未列名单」。
- [x] **PDF 文本抽取器**（P1 与 P2 的共同地基）— `scripts/supply-chain/pdf_text.py`，
      纯标准库。过滤器覆盖 Flate / ASCII85 / ASCIIHex / LZW / RunLength 与
      PNG 预测器，展开对象流。判据分四种，解不开时明说是解析器能力不足，
      **不说成「文件没有文字」**。
- [ ] **把 PDF 接进抽取器** — 抽取器的 `list_documents` 仍只收 `.htm/.html`，
      麦当劳 `formsd2026.pdf`（493KB）还是看不到。地基已就位，接线未做。
- [ ] **整份报告没有 HTML 表格** — 洛马、埃森哲、丹纳赫的 CMR 都是 33–34KB
      但 `<table>0 <tr>0`。要点开原文看名单在不在，**不要猜**。

## 四、下次怎么接着做

对话里说 **「继续开发产业链」** 或输入 **`/supply-chain`**，
会自动加载 `.claude/skills/supply-chain/SKILL.md`（口径、坑、校验、收尾）
与本文件（状态与待办），然后从 P1 往下推。

想指定方向就在后面加一句，例如：

- `继续开发产业链，先做 P1 里的 PDF 抽取`
- `继续开发产业链，这次只做校验和文档，不动数据`
- `继续开发产业链，做完直接上线`（= 明确授权合并到 main）

**不加「直接上线」时，默认做到提交分支为止，等你确认再合并。**
