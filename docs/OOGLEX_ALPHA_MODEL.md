# Ooglex Alpha 60 V1：量化选股模型规格

> 状态：V1 规格冻结，参考实现已落地  
> 代码：`scripts/alpha-model/`  
> 自检：`python3 scripts/validate_alpha_model.py`  
> 用途：研究，不构成投资建议

## 1. 模型解决的是什么问题

它不预测"某只股票三个月后涨到多少钱"。它每天回答一个排序问题：

> 在给定股票池里，未来 60 个交易日最可能跑赢基准的是哪些？

目标变量定义死：

```
Y_i(t) = R_i(t → t+60) − R_SPY(t → t+60)
```

这是**排序问题**不是回归问题，所以评价指标是秩相关（Rank IC），不是 MSE。
模型输出的分数没有收益率含义，它只表示"在今天这批股票里排第几"。

## 2. 分层原则：按数据能不能回测分，不按经济含义分

这是本规格与常见多因子设计最主要的差别。因子不按"动量/价值/质量"分组，
而是按**该因子的历史数据是不是 point-in-time** 分成三层。

| 层 | 内容 | 能否回测 | 权重 |
|---|---|---|---|
| A | 动量、反转、风险、量能（只用日线价量） | ✅ 可以 | 60 |
| B | 基本面、估值、盈利修正 | ❌ 不可以 | 40 |
| C | 宏观制度 | 不进横截面 | 0 |

### 为什么 A 层可以回测

价格历史天然 point-in-time：今天看到的 2020-03-16 收盘价，就是当时的收盘价。
复权是一个已知的确定性变换，不引入未来信息。

### 为什么 B 层不可以回测

yfinance / Yahoo quoteSummary 只提供**当前快照**。它给不出"2020 年 3 月 16 日
那天市场看到的 TTM 净利润"——那天的报表可能后来被重述过，分析师预测更是没有留档。
用今天的财务数据回测 2020 年就是未来函数（look-ahead bias），回测结果必然虚高。

所以 B 层在 V1 里**只实时使用、只前瞻验证**，不进回测。代码里这条纪律是硬的：
`build_alpha.py` 的回测路径固定传 `WEIGHTS_A`，B 层根本进不来。

### 为什么 C 层权重是 0

宏观制度对全市场是同一个值。设 `s_i = Σ_k w_k · f_ki`，若 `f_macro,i = c` 对所有 i 相同，
则 `s_i` 的**排序与 `w_macro` 完全无关**——它只是给每个人加了同一个常数。

给宏观 5% 权重不改变任何一只股票的名次。宏观只能通过三条路起作用：

1. 调节因子权重（Risk-Off 时提高风险与质量的权重）——留给 V1.5；
2. 调节持仓数量或净暴露；
3. 作为展示上下文。

V1 用第 3 条，并预留第 1 条的接口。

## 3. A 层因子清单

设 `P` 为复权收盘价序列，`V` 为成交量，`t` 为当前交易日索引。
所有因子只允许读取 `[0, t]`。

### 3.1 动量族 M（权重 30）

| 子因子 | 定义 | 子权重 |
|---|---|---|
| `mom_12_1` | `P(t−21)/P(t−252) − 1` | 0.35 |
| `mom_6_1` | `P(t−21)/P(t−126) − 1` | 0.25 |
| `rs_120` | `R₁₂₀(i) − R₁₂₀(SPY)` | 0.20 |
| `trend_200` | `P(t)/SMA₂₀₀(t) − 1` | 0.20 |

跳过最近 21 个交易日不是可选项。最近一个月存在短期反转效应，把它算进中期动量
会让两个方向相反的信号互相抵消。这是 Jegadeesh–Titman 之后的标准处理。

### 3.2 短期反转 V_rev（权重 5）

`reversal_21 = −(P(t)/P(t−21) − 1)`

取负号：最近一个月跌得多的，未来一个月倾向反弹。它和动量族方向相反且必须分开，
因为它们捕捉的是不同期限的效应。

### 3.3 风险质量 R（权重 15）

| 子因子 | 定义 | 子权重 |
|---|---|---|
| `low_vol_60` | −60 日已实现波动率（年化） | 0.35 |
| `low_maxdd_120` | −120 日最大回撤 | 0.25 |
| `low_downside_120` | −120 日下行波动率 | 0.20 |
| `low_tail_252` | −\|252 日收益 1% 分位\| | 0.20 |

统一在因子层取负号，使"分高 = 风险质量好"。这样下游不必为每个因子记方向，
少一类低级错误。

### 3.4 量能与吸筹 P（权重 10）

| 子因子 | 定义 | 子权重 |
|---|---|---|
| `volume_expansion` | `ADV₂₀/ADV₁₂₀ − 1` | 0.30 |
| `accumulation_60` | 上涨日均量 / 下跌日均量 | 0.30 |
| `near_52w_high` | `P(t) / max(P, 252)` | 0.25 |
| `volume_confirm_60` | `corr(日收益, 成交量变化率)` | 0.15 |

量能用**股数**不用成交额：成交额里含价格涨幅，用它会把动量重复算进量能因子。

## 4. B 层因子（实时可用，不进回测）

数据源 Yahoo quoteSummary（需 cookie + crumb 握手，与 v8/chart 不同）。
子因子与 A 层走**完全相同**的归一化流水线——不给它单开一条路径，
否则两层分数不在同一尺度，加权平均就没有意义。

### 4.1 基本面 F（权重 20）

| 子因子 | 来源字段 | 子权重 |
|---|---|---|
| `revenue_growth` | `revenueGrowth` | 0.20 |
| `earnings_growth` | `earningsGrowth` | 0.20 |
| `roe` | `returnOnEquity` | 0.15 |
| `operating_margin` | `operatingMargins` | 0.13 |
| `gross_margin` | `grossMargins` | 0.12 |
| `fcf_margin` | `freeCashflow / totalRevenue` | 0.12 |
| `low_leverage` | `−(totalDebt − totalCash) / ebitda` | 0.08 |

### 4.2 估值 Q（权重 10）

估值一律翻成"收益率"口径（取倒数），使**高分 = 便宜**，方向与其他因子一致。

| 子因子 | 定义 | 子权重 |
|---|---|---|
| `earnings_yield` | `1 / forwardPE` | 0.35 |
| `ev_ebitda_yield` | `1 / enterpriseToEbitda` | 0.25 |
| `fcf_yield` | `freeCashflow / marketCap` | 0.25 |
| `ev_sales_yield` | `1 / enterpriseToRevenue` | 0.15 |

取倒数时**保留负号**：亏损公司的盈利收益率为负，且亏得越狠（PE 绝对值越小）
越负，排序方向正确。行业相对性由 `sector_neutral_rank` 的行业内分位承担——
英伟达和银行比 PE 没有意义，但和其他半导体比有。

### 4.3 盈利修正 E（权重 10）

| 子因子 | 定义 | 子权重 |
|---|---|---|
| `eps_revision_90d` | 明年 EPS 一致预期相对 90 天前的变化率 | 0.40 |
| `revision_breadth` | `(上调数 − 下调数) / 分析师总数` | 0.30 |
| `eps_revision_30d` | 同上，30 天窗口 | 0.15 |
| `target_upside` | `targetMeanPrice / currentPrice − 1` | 0.15 |

修正率的**分母取绝对值**。这是最容易写错的一处：预期从 −1.00 上修到 −0.50
是改善，用带符号分母会算成 −50%，方向正好反了。自检里对这条有专门断言。

### 4.4 为什么它不能进回测

quoteSummary 只给"此刻"的快照。它给不出「2020-03-16 那天市场看到的
TTM 净利润」——那天的报表可能后来被重述，分析师预测更是没有留档。
所以 B 层只用于**今天的横截面打分**，`build_alpha.py` 的回测路径固定传
`WEIGHTS_A`，B 层从代码层面就进不去。

真正的 PIT 财务要走 **SEC EDGAR XBRL**（`companyfacts` 接口免费、无需密钥，
且每条数据都带 `filed` 日期，能重建任意历史时点的可见信息集）。那是 V2 的事。

### 4.5 接不上时会怎样

握手失败或字段缺失时**整族留空**，总分按 A 层权重重新归一化，
覆盖率降到 0.60 并如实写进输出。不用中位数填充。
此时可共振块数只有 1，候选池门槛按可得块数封顶并标记 `relaxed: true`。

诊断命令：

```bash
python3 scripts/alpha-model/fundamentals.py NVDA CSX
```

逐字段打印拿到了什么、缺了什么，区分"握手失败"与"字段缺失"两种情况。

**增速的加速度值得单列**。不是看"营收增长 30%"，而是看 12% → 16% → 21% → 28%
这个二阶差分。增速转向往往先于分析师上调预测，而上调预测又先于估值重估。

估值必须**行业内比**。英伟达和银行比 PE 没有意义。而且不是越便宜越好，
要找的是"相对于增长质量便宜"（GARP）：EPS 增速 35% / PE 30× 可能比
增速 8% / PE 20× 更有吸引力。

接入方式是外部 JSON（`--fundamentals`），不内建抓取——能提供 point-in-time
财务与分析师预测的数据源各家不同，模型不应该被绑死在某一家上。

## 5. 归一化流水线

每个横截面日**独立**执行，绝不跨日共用统计量：

```
原始值 → 去极值 → 全市场分位 / 行业内分位 → 混合 → 子因子加权
      → 族分数 → 总分 Alpha60 → 共振 Confluence
```

### 5.1 去极值

Winsorize 到 1% / 99% 分位。

### 5.2 百分位而不是 Z-score

金融数据尾部极厚。某公司去年利润接近 0，今年 EPS 增速 +2800%——这个数字真实，
但用 Z-score 归一化会让它一个人主导整张表的均值和标准差。百分位对任何单调变换
不变，天然抗尾部。

代价是丢掉"强多少"的信息。所以**评估阶段仍用原始收益**，只在打分阶段用百分位。

### 5.3 行业中性混合

```
score = λ · 全市场分位 + (1−λ) · 行业内分位,   λ = 0.5
```

纯行业中性（λ=0）会丢掉真实存在的跨行业差异；纯全市场（λ=1）会在主题行情里
让榜单被单一行业占满。行业样本少于 8 只时无法稳定排名，该股退回纯全市场分位。

### 5.4 缺失处理：不知道 ≠ 中性

缺失项**绝不用中位数或 50 分填充**。那会把"不知道"伪装成"中性"，并在
`Alpha ≥ 80` 这类过滤上系统性偏向数据缺失的股票——它们的分数方差被人为压低了，
更容易稳定地待在中上游。

正确做法：按可得项**重新归一化权重**，并如实报出 coverage。族内覆盖率低于 0.6
该族判为缺失；总覆盖率低于 0.6 该股不给分、直接剔除。

## 6. 合成与共振

```
Alpha60 = 0.30·M + 0.05·V_rev + 0.15·R + 0.10·P + 0.20·F + 0.10·Q + 0.10·E
```

### 共振 Confluence：先归并，再计票

常见做法是数"七个族里几个 > 80"。这是错的：动量、反转、量能、风险**都来自
同一份价格序列**。一只单纯涨得猛的股票能轻松拿到 4 票，看上去像多因子共振，
其实只有一条腿。

先按同源性归并成三个独立块，再计票：

| 块 | 成员 |
|---|---|
| 价格 | 动量、反转、风险、量能 |
| 质量 | 基本面 |
| 预期 | 估值、盈利修正 |

`Confluence` = 三块中分数 ≥ 70 的块数（0–3），并额外输出**块间离散度**——
离散度大说明是单腿支撑的高分股。

只跑 A 层时只有"价格"一块，此时要求两块共振在数学上不可能满足，候选池会恒为空。
所以门槛按实际可得块数封顶，并把 `relaxed: true` 显式写进输出——放宽标准可以，
偷偷放宽不行。

## 7. 分数怎么读：它不是分位数

**这是最容易误读的一点。** Alpha60 是"若干个分位数的加权平均"，因此它本身
**不是**分位数。多个 0–100 均匀分位取平均会向中间收敛，分布是钟形而不是均匀。

合成数据上的实测（120 只标的）：

```
中位 52.2    90分位 67.9    99分位 76.3    ≥80 占比 0.8%
```

所以「Alpha ≥ 80」大致是**前 1%**，不是"前 20%"。按均匀分布的直觉去读
"90–100 是 S 级、80–89 是 A 级"会得出完全错误的分级。

输出里同时给两个数：

- `alpha60` —— 加权平均分，绝对口径。市场整体弱时可以**没有人**达到 80，
  这是特性不是缺陷：候选池应该允许返回"今天没有值得研究的"。
- `percentile` —— 相对名次，永远有人在 99 分位。

分级请用 `percentile`，过滤请用 `alpha60`。完整分位对照表在输出的
`scoreDistribution` 字段里。

## 8. 硬过滤与候选池

打分**之前**的硬过滤（排除算得出但交易不了的标的，也避免它们挤占分位分布）：

- 20 日平均成交额 ≥ 2000 万美元
- 收盘价 ≥ 5 美元
- 有效历史 ≥ 252 个交易日
- 最近 20 个交易日缺失 ≤ 2 天

打分**之后**的候选池（三条同时满足）：

- `Alpha60 ≥ 80`
- `Risk ≥ 50`
- `Confluence ≥ 2`（按可得块数封顶）

目标是把约 500 只压缩到 20–30 只**值得人工读财报**的股票。
候选 ≠ 买入，它只是把人工研究的注意力集中到该去的地方。

## 9. 验证协议：模型能不能用，只由这里裁决

### 9.1 三个核心指标

1. **Rank IC** —— 每个评估日，`Spearman(分数, 未来60日超额)`
2. **分组单调性** —— 按分数分 10 组，看 D1…D10 的平均超额是否单调
3. **扣成本后的多空价差** —— D1 减 D10

分组单调性比"Top10 赚钱"重要得多。只有 Top 组好、中间乱序，说明排名本身
不可信，赚钱可能来自少数几只票的运气。

### 9.2 验收线（跑之前就固定，写死在 `config.py`）

| 项 | 阈值 |
|---|---|
| IC 均值 | > 0.02 |
| IC 信息比 | > 0.30 |
| IC 胜率 | > 55% |
| IC 可与 0 区分 | \|t\| > 2（Newey–West） |
| 分组单调秩相关 | < −0.70 |
| D1 − D10 | > 0 |
| 扣成本后组合累计超额 | > 0 |

任一项不过，V1 判为不可用。**不许看到结果再改标准。**

### 9.3 三条统计纪律

**重叠窗口与统计功效（V1 首次实跑后修正）。** 60 日前瞻收益在日频上高度自相关，
按日算 IC 会把有效样本量夸大约 60 倍。原设计的对策是强制不重叠窗口——
统计上干净，但**功效低到没法用**：5 年历史只剩 16 个独立样本，
IC 标准误 0.049，95% 区间宽达 ±0.10。连本规格自己的 `IC > 0.02` 门槛都测不出来
（要让 IC=0.02 达到 t=2，按实测 IC 波动率需要约 **91 年**历史）。

结果就是"未通过"和"测不出来"分不开——而这两件事的后续动作完全相反。

现在改为：**密集评估（每 10 个交易日一次）+ Newey–West 修正标准误**
（Bartlett 核，滞后 = 前瞻期 ÷ 评估间隔）。既拿回统计功效，又不虚报显著性。
不重叠的子集仍然计算，作为交叉核对——两者应当同号同量级。

验收线因此**新增一条**：`IC 可与 0 区分`（|t| > 2）。

需要说清楚的是：这不是因为模型没通过就放宽标准。**六条原有阈值一个没动。**
改的是**测量方法**——原估计量的功效缺陷与结果好坏无关，用合成数据也一样存在。
新增的那条不是门槛，是把"没通过"和"判不了"分开的标签。

**逐因子分解。** 总分失败时唯一有用的东西：对每个子因子和每个族单独算 IC 与
Newey–West t 值，按均值降序排。它回答的是"是全都没用，还是有几个有用但被
没用的稀释了"。报告页用实心/空心点标注 |t| 是否大于 2 ——
**颜色只表示方向，不表示可信度**。

**持有期必须与 IC 口径一致。** 此前组合只持有 21 日，而验收线测的是 60 日 IC——
同一个模型两个口径，于是跑出过「IC = 0.0001（t = 0.00）但组合累计超额 +240%」
这种自相矛盾的结果，报告页却没有任何提示。

模型叫 Alpha 60、声称预测 60 日超额，用于验收的组合就必须持有 60 日。
现在**两个持有期都跑**：60 日为验收口径，21 日为对照。
两者差异本身也是信息——差得远说明信号衰减快。

**IC 与组合矛盾时，报告页主动提示两种可能：**

1. **IC 测全体单调性，Top-N 组合只吃极端头部。** 信号若只存在于前 5%，
   全体秩相关会接近 0 而 Top-N 照样好看。看分组图能确认：
   只有 D1 孤立突出、D2–D10 乱序，就是这种情况。
2. **选择偏差**——见 9.5 的暴露度指标。

**先验提醒**：年化超额超过 10% 且最大回撤很浅的回测结果，在真实世界里极其罕见。
**先怀疑偏差，再考虑 alpha。**

**交易成本。** 换手率按被替换仓位比例计，买卖各付一次单边成本（默认 10bp），
即本期成本 = 2 × 换手率 × 单边费率。年化 25% 的毛收益在 300% 换手下
可能只剩十几个点。alpha 不是预测的收益，是扣完摩擦还剩下的收益。

**多重检验。** 试了 N 个因子后挑最显著的那个，它的 t 值天然偏高：即使全部无效，
纯靠运气也会出现约 `N × 4.55%` 个 |t| > 2。V1 实跑测了 13 个 A 层子因子，
期望假阳性 0.6 个，实际观察到 3 个——看起来"有发现"，但 Bonferroni 校正后
需要 |t| > 2.89 才算确立，最强的 −2.2 没过。

因子之间高度相关时 Bonferroni 过于保守（三个低波动因子测的是同一件事），
所以同时给出按约 10 个独立因子群算的阈值。两个数都写进输出与报告页。

**没过校正线的因子属于「值得追查」，不是「已确立」。**

**尝试台账。** 上面那条讲的是「一次运行里测了多少个因子」；这条讲的是
「你一共跑了多少次」。看过结果之后再改模型，改动就带着「已经看过答案」的污染：
试十个变体挑最好的，即使十个全是噪声，出现至少一个 |t|>2 的概率也有 37%。

`variants.py` 因此做两件事：

1. **变体必须具名并写进代码**，每个都要写清「为什么试它」，理由必须来自数据。
   不允许在 config 里随手改个数字跑一次就忘了。
2. **每跑一次回测就往台账追加一条**，阈值按累计次数收紧
   （`alpha / 2N`），报告页显示「这是第 N 次尝试」与打折后的 |t| 门槛。

| 累计尝试 | 至少一次假阳性概率 | 需要 \|t\| > |
|---|---|---|
| 1 | 4.5% | 1.96 |
| 3 | 13.0% | 2.39 |
| 6 | 24.4% | 2.64 |
| 10 | 37.2% | 2.81 |
| 20 | 60.6% | 3.02 |

台账文件 `scripts/alpha-model/variant_ledger.json` **只增不改，且随代码进版本库**
——刻意不放在 `output/` 或 `cache/` 下，那两个目录会被「清缓存重跑」一并删掉。
它的全部价值就在于「试了多少次」这个数字无法被顺手抹掉。

这是「试到出结果为止」的唯一解药：**让每多试一次都变贵，而不是免费。**

**子区间稳定性。** 单个 t 值把整段历史压成一个数，制度切换被平均掉了。
把评估期切成三段分别算 IC，才分得出两种情况：

| 现象 | 含义 | 该怎么做 |
|---|---|---|
| 三段同号 | 稳定的因子方向 | 哪怕是负的也可以反向使用 |
| 符号翻转 | 随市场制度变 | 一段历史上的显著性不能外推 |

**这一条比任何单一 t 值都更能说明问题**，也是决定「方向真的反了」还是
「这段历史恰好不友好」的唯一办法。

### 9.4 行情粒度校验（V1 实跑中踩到的坑）

**Yahoo 在超长区间下会静默把 `interval=1d` 降级成周线或月线，响应里没有任何字段
说明这件事。**

实际发生过：`--range max` 请求 SPY 日线，返回的是上市至今的 **403 个月线 bar**。
模型把每个月当成一个交易日，于是：

| 名义 | 实际 |
|---|---|
| 60 个交易日前瞻 | 60 个月 = 5 年前瞻 |
| 12 个月动量 | 231 个月 ≈ 19 年动量 |
| 20 日平均成交额 | 20 个月平均 |

**全程不报错**，所有指标都是"看上去正常"的数字——`D1 − D10 = −70.92%` 这种量级
才是唯一的破绽。这类错误比崩溃危险得多。

对策：`prices.py` 的 `infer_interval()` 从日期序列反推真实粒度（相邻 bar 的中位
间隔，日线跨周末最多 3 天）。非日线直接抛 `NotDailyDataError` 终止整轮，
宁可失败也不用降级数据跑完全程。缓存命中时同样校验。
输出与报告页都带 `barInterval` 字段，非日线时首屏红色告警。

**不要用 `--range max`，用 `--range 10y`。**

### 9.5 幸存者偏差暴露度

股票池按今日市值降序排列，因此随机挑选的「今日排名分位」均值恰好是 **50**。

统计策略历次选中标的的今日排名分位：明显低于 50（排名更靠前）说明策略在多年前
选出的，恰好是今天最大的那批——收益里有多少来自预测能力、多少来自
「我们只把赢家放进了池子」，就分不开了。

这是**暴露度不是修正**，减不掉。合成数据上该指标为 50.3 / t = −0.23，
即无偏差时正确地报告无偏差。真正的解法是 point-in-time 成分股。

显著暴露时报告页会直接写出：**上面的组合收益不能当作 alpha 的证据。**

### 9.6 已知偏差，必须随结论一起披露

**幸存者偏差 + 前视选择偏差。** 默认股票池取自 `apps/companies/data.json`——
"今天"的市值榜。用它回测过去，模型等于事先知道了哪些公司活下来并变大。
这会系统性抬高全部回测收益，对动量因子的抬高尤其严重：今天的大公司
正是过去涨得最多的那批。

因此 **V1 的回测只能用来否决坏模型，不能用来证明好模型。**
修掉它需要 point-in-time 成分股历史，属于 V2。

### 报告页

`scan` 与 `backtest` 跑完会在 JSON 旁边生成同名 `.html`，**双击用浏览器打开即可**，
不需要起服务、不占端口、不装任何东西。

刻意不做成 Streamlit 一类的服务端应用：那要多装 streamlit / pandas / numpy，
要管进程和端口，还没法归档转发。报告页把数据在生成时就渲染进 HTML，
页面不做任何 `fetch`——`file://` 下的 fetch 会被 CORS 挡掉，
靠外部 JSON 的页面在本地根本打不开。

页面内容：

| 区块 | 作用 |
|---|---|
| 数据徽标 | 数据源、数据日期、日频非实时、完整/部分/过期状态；合成数据首屏黄底告警 |
| 一眼看全 | 股票池 → 通过过滤 → 候选池的漏斗，加总分中位与 ≥80 占比 |
| **总分分布直方图** | 最重要的一张图：让「80 分是极端尾部而非前 20%」肉眼可见，红线标门槛 |
| 排名表 | 每族分数的内联条 + 数字，数字保证读数不依赖颜色 |
| 行业分布 | 单色横条；11 个行业超出配色能承载的类别数，不用彩虹色 |
| 逐只拆解 | 七族分数、拉高的三个因子、拖后腿的三个因子、缺失因子、单腿支撑告警 |
| 边界说明 | 分数不是收益预测、候选不等于买入、幸存者偏差、共振降级 |

回测报告另有六条验收线的通过/未通过清单、Rank IC 卡片、
**十分组柱状图**（蓝正红负，看的是 D1→D10 是否单调）与扣成本后的组合指标。

图表遵循的几条：单序列只用一个色相不加图例（标题已说明画的是什么）；
分布用连续直方图、离散分组用封顶柱宽；正负极性才用蓝↔红发散配色；
状态一律「图标 + 文字 + 颜色」三重编码，不让颜色单独承载含义；
明暗两套配色都跑过对比度、色觉障碍分离度与色度下限校验。

### 自检覆盖什么

80 项断言，六类：

1. **数学基本功** —— 分位、去极值、区间收益、回撤、秩相关，对着可手算的答案；
2. **未来函数守卫** —— 把 `t` 之后的价格 ×7、成交量归零、基准腰斩，
   `t` 时刻的 13 个因子值必须一字不变。这是整套代码最关键的一条断言；
3. **缺失语义** —— 缺数据必须是 `None`，不能被填成 50 分；
4. **端到端双向** —— 埋了信号的合成市场必须找得出来，纯噪声市场必须找不出来。

5. **B 层解析器** —— 对着固定样本断言 15 个子因子的每一个算式，
   含亏损公司修正方向、负市盈率排序、零分母、空响应、部分响应等边界。

6. **行情粒度校验** —— 复现 `range=max` 返回 404 个月线 bar 的真实事故，
   断言它被识破而不是被当成日线跑完全程。

第 4 条的后半句比前半句重要，它证明这套代码不会从随机数里造出 alpha。
实测（100 只标的、1800 个交易日）：

| | 有信号 | 纯噪声 |
|---|---|---|
| IC 均值 | 0.4924 | −0.0307 |
| IC 信息比 | 5.03 | −0.24 |
| 分组单调性 | −0.988 | +0.685 |
| 组合累计超额 | +18.12 | −0.147 |
| 六条验收线 | 全部通过 | 全部不通过 |

纯噪声上的 −14.7% 恰好是换手成本的拖累（年换手 3.47，成本累计 4.2%）——
这正是一个诚实的回测引擎在没有 alpha 时该给出的结果。

## 11. 版本路线

| 版本 | 内容 | 前置条件 |
|---|---|---|
| **V1** | 规则型多因子，固定权重，A 层可回测 | 已落地 |
| V1.5 | 权重由 IC 决定而不是拍脑袋；宏观调节权重 | V1 跑满 1 年实盘记录 |
| V2 | Point-in-time 成分股 + PIT 财务，B 层进回测 | 换数据源（付费） |
| V3 | GBDT（XGBoost/LightGBM）学习非线性组合 | V2 积累足够样本 |
| V4 | 分别训练 20/60/120 日模型并集成 | V3 单模型验证通过 |
| V5 | 组合优化 + 风险模型 + 执行成本模型 | 前置全部通过 |

**不要跳级。** 直接上机器学习会得到一个无法解释、无法排错、且很可能在
未来函数上训练出来的模型。V1 的三个目标只有：数据正确、排名稳定、能解释。

到 V3 时，人工权重被替换成：

```python
model.fit(X_train, y_train)   # X = 各因子分数, y = 未来60日超额
```

机器可能发现动量在牛市重要、Risk-Off 时没用，或者盈利修正与营收加速
同时出现时效果远大于单独出现——这就是非线性 alpha。但它必须建立在
V1/V2 已经把数据管道和验证协议做对的基础上。

## 12. 相对常见设计的修正

本规格与"七因子加权、宏观占 5%、Alpha 90–100 为 S 级"那类常见设计的差别，
集中在五处：

1. **宏观权重从 5% 改为 0**，理由是横截面方差为零的变量不改变任何排名——
   这是数学事实，不是偏好。
2. **因子按能否回测分层**，B 层基本面明确排除出回测，避免用今天的财报
   回测三年前。
3. **共振先归并同源因子再计票**，否则价格类因子重复计数，单腿股票伪装成共振。
4. **明确总分不是分位数**，「≥80」实测是前 1% 而非前 20%，分级口径必须改用
   `percentile`。
5. **补上统计诚实性**：重叠窗口、多重检验、幸存者偏差三条，前两条写进代码，
   第三条写进每份回测输出的 `knownBiases`。
