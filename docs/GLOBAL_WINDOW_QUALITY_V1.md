# 环球实景 WINDOW V1.0 质量标准

## 目标

V1.0 不以“凑满数量”为优先，而以统一的沉浸质量为优先。所有自动进入生产 R2 manifest 的视频必须同时满足技术硬门槛、场景语义门槛和 100 分质量评分。

## 硬门槛

新视频在下载到 R2 之前先读取 Wikimedia Commons 官方文件元数据并检查：

- 时长：至少 30 秒，最多 300 秒。
- 推荐时长：60–180 秒。
- 分辨率：至少 1280×720。
- 方向：必须横屏，宽度必须大于高度。
- 单文件：最多 80 MB。优先使用 Wikimedia TimedMediaHandler 官方 1080p/720p 转码；原始大文件继续作为版权/来源依据，但不要求原片本身低于 80 MB。
- 授权：仅接受既有白名单中的自由许可。
- 内容：继续拒绝人物主体、活动、体育、新闻、交通主体、动物主体、宣传片、合集、蒙太奇、幻灯片等。
- 去重：同场景近重复继续拒绝。
- 地理：保持既有 GPS / 地名双重校验。

任何一项硬门槛不通过，都不能进入上传计划。对于原片超过 80 MB 的视频，V1.0 会先检查 Wikimedia 官方 derivatives：只要存在 ≥720p、横屏、估算/实际 ≤80 MB 的 WebM/MP4 官方转码，仍可合规入库；manifest 会同时保留原始 URL 与实际交付转码信息。

## 100 分评分

通过硬门槛后再计算 V1.0 质量分：

| 维度 | 满分 | 说明 |
|---|---:|---|
| 画质 | 25 | 720p 合格，1080p 优先，2K/4K继续加分 |
| 时长 | 20 | 60–180 秒满分，30–59 秒或 3–5 分钟适当降分 |
| 场景 | 25 | 雨雪、夜景、海岸、山景、湖泊、河流、森林、日出日落等沉浸场景 |
| 稳定性 | 15 | 固定/长镜头优先；航拍、hyperlapse 等降低分数 |
| 沉浸感 | 15 | 场景语义越明确、越接近持续窗景越高 |

生产最低分：60 分。

这套评分是“元数据 + 标题/描述语义”的可重复规则，不冒充计算机视觉主观审片。后续若加入真实帧分析，应另起质量 schema 版本。

## 中文标题

前端主标题使用中文展示名，例如：

- 东京 · 雨景
- 札幌 · 雪景
- 威尼斯 · 水岸
- 冰岛南岸 · 云雾

manifest 同时保留：

- `name` / `name_zh`：中文展示名
- `original_title`：Wikimedia 原始文件标题
- `city` / `country`：原始英文地理字段
- `city_zh` / `country_zh`：中文地理字段

因此中文化不会破坏来源、版权或原始素材追溯。

## 前端技术信息

列表和播放器元信息显示：

- 中文地点
- 中文场景分类
- 720p / 1080p / 4K
- 视频时长
- 许可证

原始英文文件名不再作为主标题，但仍可通过素材来源和 manifest 查到。

## 存储预算

单条视频上限 80 MB，整个 active manifest 的视频总量上限为 8 GiB。

构建器会按质量分优先排序；如果加入某条视频会导致 active catalog 超过 8 GiB，该条视频不进入本轮 manifest。

这个 8 GiB 是 active catalog 预算，不代表整个 Cloudflare R2 账号绝对不会暂时更高：部署过程中可能短暂同时存在上一版与新版对象，另外账号里还可能有其他 bucket。

## 现有视频迁移

旧 R2 视频不会因为“已经存在”而自动豁免。V1.0 会重新查询其 Wikimedia 文件元数据并重新评分。

不满足 30 秒、720p、横屏、5 分钟上限或 60 分质量线的旧视频，不进入 V1.0 manifest。

首次迁移先运行 `--audit-existing`，只统计，不上传、不删除。2026-10-01 的现网审计结果为：22 条通过，75 条因时长/分辨率/横屏等技术条件失败，2 条因场景语义失败。旧对象不批量一次删除；退出新 manifest 的对象进入持久清理队列，每次生产运行最多删除 20 个，直到清完。

## 发现策略

V1.0 采用 **Global-First**：生产构建不再先逐城市扫描本地点，而是直接从扩大的全球景观查询/类别池中筛选，再用 GPS 与地名映射到 172 个地点。原因是实测本地点优先会提前占用去重与地点配额，使严格目录停在 99 条；Global-First 在不降低任何质量门槛的情况下，已稳定构建 100 条、覆盖 41 个地点。

## 安全发布

生产发布仍遵循：

1. 先生成完整新 manifest。
2. 验证数量、质量、时长、分辨率、版权、地理分布、总容量。
3. 上传新增 R2 对象。
4. 上传 manifest。
5. CDN Range 播放验证。
6. 最后才处理退出目录的旧对象。

任何前置检查失败，都不得用空目录或低质量目录覆盖上一份有效 manifest。

## 当前状态

V1.0 仅在 `window-v1.0-quality-gates` 分支开发。未经所有者明确批准，不合并 `main`，不部署生产。
