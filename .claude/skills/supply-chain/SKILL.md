# 全球产业链：持续开发

这个板块是一项长期工程，不是一次性任务。每次接手先读
`docs/SUPPLY_CHAIN_BACKLOG.md`（当前状态与待办），再动手。

## 一、不可越过的线

**框架可以用行业通识建，公司间的关系必须有出处。**

| | 依据 | 例子 |
|---|---|---|
| 价值链环节、SIC 分类 | 行业通识 + SEC 官方码，是**定义**不是断言 | 「半导体属于零部件层」不需要出处 |
| 公司 → 公司/冶炼厂的关系 | **必须**有可点开的原始申报（sourceType + https + docDate） | 「台积电给苹果代工」我知道，但给不出可核验文件，就不上图 |
| 产业链归属（横轴） | 同上，是**分类**：由申报的 SIC 码按公开规则映射，一家可多归属 | 「ASML 在半导体链上」是定义；「ASML 供货给台积电」要出处 |

模型的行业知识**不是数据源**。凡是画不出出处的关系，一条都不写进 `edges/`。

其余三条同等重要：

1. **空缺要画出来。** 没有数据的环节照画，画成灰色 0 条，并在图注里点明有多少家
   不在图中。只画有数据的部分会让读者以为那是全貌。
2. **语义写申报原义。** 冶炼厂关系是「该冶炼厂出现在申报人的供应链中」——间接、
   不含份额、不含层级。**不得写成「供应商」**，那是替申报人下的结论，而且是错的。
3. **不拿坏结果覆盖好数据。** 抽取器有整轮保留阈值（`MIN_KEEP_RATIO`），
   本轮拿到的公司数低于磁盘已有的 60% 就中止，保留旧数据。

## 二、这个项目反复踩过的坑

按时间顺序，每一条都真实发生过，改对规则**没有一次是靠自动结论**，
全是靠把原始数据打出来看：

- 探针的自动结论说「2/8 家可用」，实际只有 1 家——把《可持续发展报告》
  当成了供应商名单。
- 探针报「40 家有看不到的文件」，那些是 0 字节的索引文件，一个都不是损失。
- 「丢弃行数」被当成漏收的冶炼厂，实际是国名附录。
- `Gold (Au)` 里的元素符号让迪尔 402 家真冶炼厂全被丢弃。
- 修上一条时矫枉过正，连国别一起丢，六家公司的名单整份消失（88 → 80 家）。
- 按两位 SIC 码把 40–47 整段归物流，会把邮轮和客运航空当成货运。

**共同的方向：都是把结果说多。** 所以每次改判据之前，先把原始丢弃行、
原始字段名、原始文件清单打出来看；结论由人看数据得出，不由脚本的计数决定。

还有一条相反方向的：**我以为应用材料是设备商所以该进资本设备层，但它的备案
SIC 是 3674 半导体**。不能因为知道一家公司做什么就按公司名覆盖行业码，
否则「判定依据」那一列就是假的。

## 三、先探后建

新数据源一律先写只读探针（`scripts/supply-chain/probe_*.py`），
在 Actions 里跑，把真实结果打进日志人工核对，再决定接不接。
探针**不写任何数据文件、不建任何边**。

已探过的结论见 `docs/SUPPLY_CHAIN_BACKLOG.md` 的「数据源判决」一节，
否决过的不要重复探。

## 五、四道校验，缺一不可

```bash
python3 scripts/validate_supply_chain_extraction.py   # 解析规则断言（离线）
python3 scripts/validate_supply_chain_graph.py        # 发布契约：无证据不上图
python3 scripts/validate_asset_versions.py --stamp    # 静态资源版本号（全站）
node    scripts/validate_supply_chain_page.mjs        # 浏览器渲染契约，三档视口
```

改了页面就补断言。**断言要盯「画的是不是那个数」，不是「画出来了没有」**——
拿 nodes.json 逐条比对，而不是比对页面自己算出来的值。

`--stamp` 那一道是全站的，而且是有来由的：2026-09-03 用户手机上苹果页显示
「本页已收录 20245 条」（真值 0），根因是 `company.js` 没有版本号而 JSON 用了
`no-cache`——新数据配旧代码。
